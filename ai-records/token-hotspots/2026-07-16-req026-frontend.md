## 后续优化建议

1. **document-lifecycle 按 §5.0 scope 严格裁剪**：文档回写类任务只读 §7.1（状态词典）/ §8（E6 反向同步）/ §9（变更传播）/ §10（声明）/ §11（自检），跳过 §2-5.5（多入口 / 剖面 / UI 原型门禁）。§5.0 已有「按 scope 读取」导航表，应更严格遵循。
2. **编码规则包去重 / 速查**：`global-rules` / `implementation-lifecycle` / `project-rules` / `run-dev-task` 在「先设计后实现 / 小步快跑 / 状态据实 / 修改前确认」上有职责重叠。可在 `index.md` 为「编码 Sprint」「文档回写」等高频任务提供「最小必读章」速查卡，减少全文件读取。
3. **大文件探索策略**：App.tsx 类大文件先 `wc -l` 评估 + Grep 定位关键符号行号，再按需读行段，优于盲目分段多次 Read。
4. **第三方库运行时行为验证**：build（tsc）只覆盖类型 / 语法，不覆盖 markdown 解析 / url sanitization 等运行时语义。对「依赖库隐式行为」的关键路径（如自定义 scheme、组件拦截），用 `node` + `react-dom/server` SSR 做最小验证是低成本高价值补充——本轮据此避免交付一个「build 绿但 wikilink 失效」的缺陷。
5. **文件膨胀前置处理**：`App.tsx`（~670）/ `api.ts`（~414）已超 / 接近阈值（memory），本次为避免混入无关改动未拆分。建议下个 slice 前先做拆分（Sprint-0′ 4b handler→hooks，或 api 按域拆），避免继续累积。
