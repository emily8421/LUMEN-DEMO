## 3. 阶段路线图

> 路线图原则：**先以 Demo 跑通核心价值闭环（Phase1），再递进到 MVP（Phase2），远期愿景视技术验证决定是否纳入。**
> 每个阶段按 global-rules §8.1 同时声明**功能范围**（`[P1]` / `[P2]` / `[愿景]`）与**交付物形态**（Demo / MVP / 产品），按"原位增量"落地——升阶段不重写需求，只动 04-08 的细节。

**阶段双维度总览**（一眼可见交付物形态演进；各阶段详情见下方子节）：

| 阶段 | 功能范围 | 交付物形态 | 状态 | 进入标准 | 退出标准 |
|---|---|---|---|---|---|
| Phase1（当前） | `[P1]` · REQ-001..011、REQ-036；P1.5 候选 REQ-027/037/038 | **Demo** | 当前（P1.5 候选待编码） | 项目起点（无前置 Phase）；P1.5 以 Phase1 Demo closure 为前置 | REQ-001..011、REQ-036 可演示 + REQ-009/010 降级边界清晰 + P1.5 候选按 Sprint-16~18 验收 + 产品红线未被破坏 |
| Phase2（优化扩展） | `[P2]` · MVP 必做 REQ-012/014/025/026（+ 可选 013/024；REQ-027 已提前 P1.5） | **MVP** | 范围已调整（核心 4 项） | Phase1 / P1.5 底座已实现；04/05 Phase2 设计补强 + tech-env-eval + 06/07 契约齐备（见 research 评估） | 核心 4 项 MVP 可真实上线 + 验收 TC（09 Phase2 用例，启动时细化）；REQ-009/010 真实化按 MVP 口径评估；产品红线未破坏 |
| 远期愿景（不承诺时间） | `[愿景]` · REQ-018..023、REQ-028..035 | **产品** | 骨架 | 05 技术验证高难度 AI 可行 | 不承诺时间 |

### Phase1 —— 当前（功能范围 `[P1]` · 交付物形态 **Demo**）
- **目标**：在双空间隔离 + 三级权限下，跑通"导入 → 检索 → 问答带来源 → 编辑留版本 → 术语对齐"的最小闭环，演示 LUMEN 核心价值。
- **功能范围 `[P1]`**：REQ-001..REQ-011、REQ-036（U-01..U-12、U-42）。
- **交付物形态 Demo**：核心价值可演示，可用最简实现 / 明确 Mock，**保留产品红线**（库外问答回复"未找到"、不编造）；不默认称为 MVP。
- **演示场景**：Kira 入职第一天，用搜索 + 问答定位"场景联动 200ms 延迟约束"，答案带来源，并按 brightlite-team 术语表解释"触发延迟"。
- **进入标准**：本阶段即项目起点（无前置 Phase）。
- **退出标准（Demo 验收）**：REQ-001..011、REQ-036 全部可演示（见 `docs/09-verification.md` §2 矩阵）；其中 REQ-009/010 以 `.md` / `.txt` 已提取文本降级演示，真实 Word / PDF 解析与 OCR 不作为 Phase1 Demo 退出阻塞；产品红线未被破坏。

### Phase1.5 —— 可用性收口（功能范围 `[P1]` · 交付物形态 **Demo 可用性增强**）
- **目标**：在不切入 Phase2 MVP 的前提下，补齐日常当工具最痛的批量导入与导出能力。
- **功能范围 `[P1]`**：REQ-037 批量 / 文件夹 `.md` / `.txt` 导入、REQ-038 单文档 `.md` + 空间 ZIP 导出、REQ-027 单文档 PDF 导出（从 Phase2 提前，受 RG-006 门禁）。
- **交付物形态 Demo 可用性增强**：仍属于 Phase1 收口，不等同于 Phase2 MVP；不引入标签 / 内链 / AI 润色等 P2 能力。
- **进入标准**：Phase1 Demo closure 已完成；Sprint-0′ 框架补课不阻塞 P1.5；REQ-027 编码前必须先完成 PDF 库选型与中文最小样例验证。
- **退出标准（P1.5 验收）**：Sprint-16 / 17 按 TC-P1-015 / 016 通过；Sprint-18 仅在 RG-006 Go / Conditional Go 后按 TC-P1-017 通过；导出产物继承权限过滤，产品红线未被破坏。

### Phase2（优化扩展）（功能范围 `[P2]` · 交付物形态 **MVP**）
- **目标**：补知识组织、写作辅助与交付能力，从"能用"到"好用"。
- **功能范围 `[P2]`（MVP 必做，2026-07-15 调整）**：REQ-012 标签视图、REQ-026 内部链接 + 反向链接、REQ-014 AI 润色 + 写作引用、REQ-025 快速录入索引条目（核心 4 项；REQ-027 已提前至 P1.5；原 Phase2 MVP 范围建议见 `docs/research/2026-07-11-phase2-mvp-scope-recommendation.md`）。
- **可选（视精力）**：REQ-013 时间轴视图（先不做关联图）+ REQ-024 时间轴密度热条。
- **不进 Phase2 MVP（留后续 Phase）**：REQ-015 跨空间推送、REQ-016 多人协作、REQ-017 移动端——重依赖 / 安全敏感；候选子范围替代（单向外链 / 评论·锁 / 桌面响应式）待确认（PH2-C-003）。阶段标签仍 `[P2]`，但不进 Phase2 MVP 验收。
- **交付物形态 MVP**：可真实上线使用，补齐 Phase1 Demo 缺的生产要素，而非演示原型。
- **进入标准**：Phase1 / P1.5 文档 / 权限 / 检索 / 导入导出底座已实现；`04/05` Phase2 设计补强（MOD-006/007 + Phase2 ADR）、Phase2 tech-env-eval（Go / Conditional-Go）、`06/07` MVP 级契约齐备。
- **退出标准（MVP 上线验收）**：核心 4 项可真实上线且有验收 TC（`09` Phase2 用例，启动时细化）；REQ-009/010 真实化（真实 Word / PDF、OCR）按 MVP 口径纳入评估；产品红线未被破坏。

### 远期愿景（不承诺时间）（功能范围 `[愿景]` · 交付物形态 **产品**）
- **目标**：补存量知识接入、**情报分析（i2 精神）**、情报交付能力——情报分析（路径推理 / 矛盾检测 / 证据地图等）是 v18 强调的远期差异化方向。
- **功能范围 `[愿景]`**：REQ-018..REQ-023、REQ-028..REQ-035。
- **交付物形态 产品**：愿景最终交付物默认为产品，全功能生产化、覆盖运营级要求；本阶段不承诺时间。
- **前置**：热力矩阵 / 因果推理 / 矛盾检测 / 假设检验等高难度 AI 需 05 技术方案验证可行后再纳入某 Phase。
