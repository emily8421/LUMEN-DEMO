## 2. 优先级

- **P0（MVP 必须）**：空间隔离 + 权限、文档 CRUD + 版本、全文搜索、RAG 问答、多格式导入 + OCR
- **P1（MVP 重要）**：桌面端体验、私有文档
- **P2（后续）**：导航视图、AI 润色、跨空间推送、协作、移动端
- **待验证（不承诺阶段）**：热力矩阵、因果推理、Vault 挂载、对外简报（依赖未定的数据来源或高难度 AI，需 05 技术验证后再定阶段）

## 3. 阶段路线图

> 路线图原则：**先以 Demo 跑通核心价值闭环（Phase1），再递进到 MVP（Phase2），远期愿景视技术验证决定是否纳入。**
> 每个阶段按 global-rules §8.1 同时声明**功能范围**（`[P1]` / `[P2]` / `[愿景]`）与**交付物形态**（Demo / MVP / 产品），按"原位增量"落地——升阶段不重写需求，只动 04-08 的细节。

### Phase1 —— 当前（功能范围 `[P1]` · 交付物形态 **Demo**）
- **目标**：在双空间隔离 + 三级权限下，跑通"导入 → 检索 → 问答带来源 → 编辑留版本"的最小闭环，演示 LUMEN 核心价值。
- **功能范围 `[P1]`**：REQ-001..REQ-011（U-01..U-12）。
- **交付物形态 Demo**：核心价值可演示，可用最简实现 / 明确 Mock，**保留产品红线**（库外问答回复"未找到"、不编造）；不默认称为 MVP。
- **演示场景**：Kira 入职第一天，用搜索 + 问答定位"场景联动 200ms 延迟约束"，答案带来源。
- **进入标准**：本阶段即项目起点（无前置 Phase）。
- **退出标准（Demo 验收）**：REQ-001..011 全部可演示（见 `docs/09-verification.md` §2 矩阵），且产品红线未被破坏。

### Phase2（优化扩展）（功能范围 `[P2]` · 交付物形态 **MVP**）
- **目标**：补导航与协作能力，从"能用"到"好用"。
- **功能范围 `[P2]`**：REQ-012..REQ-017（标签 / 时间轴 / 关联图、AI 润色、跨空间推送、多人协作、移动端）。
- **交付物形态 MVP**：可真实上线使用，补齐 Phase1 Demo 缺的生产要素（导航 / 协作 / 移动端），而非演示原型。
- **依赖 / 进入标准**：Phase1 的文档 / 权限 / 检索底座已实现。
- **退出标准**：待升阶段时细化（MVP 上线验收口径）。

### 远期愿景（不承诺时间）（功能范围 `[愿景]` · 交付物形态 **产品**）
- **目标**：补存量知识接入、**情报分析（i2 精神）**、情报交付能力——情报分析（路径推理 / 矛盾检测 / 证据地图等）是 v18 强调的远期差异化方向。
- **功能范围 `[愿景]`**：REQ-018..REQ-023、REQ-028..REQ-035。
- **交付物形态 产品**：愿景最终交付物默认为产品，全功能生产化、覆盖运营级要求；本阶段不承诺时间。
- **前置**：热力矩阵 / 因果推理 / 矛盾检测 / 假设检验等高难度 AI 需 05 技术方案验证可行后再纳入某 Phase。

## 4. 非目标（明确不做，防范围蔓延）

- **Phase1 不做**：任何高级视图（时间轴 / 关联图 / 热力矩阵 / 气泡图谱 / 标签）、跨空间推送、对外简报、Vault 挂载、录音转写、实时协作、移动端。
- **全程不承诺**：除非 05 验证可行，否则不实现 跨文档因果推理、问题热力矩阵。

完整禁止清单见 `ai/project-rules.md` §1。
