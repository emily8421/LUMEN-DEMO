# LUMEN 前端交互设计 · 发散性方向探讨

## 0. 写作前提

本篇刻意**搁置** kb-prd-v5、kb-architecture-v2 中已经写死的"三栏布局""目录树为主导航"等既有结论，只从 kb-scenario-v19 的叙事本身出发，重新想一遍：**如果 LUMEN 的界面完全没有被任何已有实现束缚，它应该长什么样？**

这样做的理由：PRD 里的三栏布局是"知识库软件"的默认答案——几乎所有笔记/Wiki工具都长这样（前三份文档描述的三款产品都是这个范式的变体）。但 LUMEN 的场景文字讲的其实不是"记笔记"，而是**"在信息中发现关系、发现矛盾、发现别人没看见的线索"**——Mark 在关联图里绕一圈发现隐性耦合风险，Alice 用证据地图给假设称重，Kira 靠标签视图和术语悬浮在第一天就摸清楚了别人几个月的脉络。这是**情报分析（i2）的叙事内核**，而三栏笔记软件的骨架天然不是为这件事设计的。所以这次要做的是：先质疑骨架本身，再决定要不要用它。

---

## 1. 先问一个问题：LUMEN 的"第一眼"应该是什么？

三款参照产品的首页第一眼分别是：知识库Wiki 是"目录+彩色气泡"，印象笔记是"文件夹树+文档列表"，ima 是"图标导航+订阅列表"。三者共同点是：**先给你一个组织结构，再让你往里钻。**

但 LUMEN 场景里反复出现的高光时刻，都不是"打开文件夹找到了什么"，而是"**盯着一张图，突然看懂了一件之前没人看懂的事**"——Mark 那句"这一节不是他计划写的，是关联图让他看见的"，几乎可以当作产品的核心主张来读。

如果这是产品真正想让用户体验到的东西，那么首页第一眼**不应该是目录树**，而应该是**一整块可以让人"盯着看"的画布**。目录树、文件列表这些"找东西"的功能不是不需要，而是应该退居为**辅助手段**，而不是主入口。

---

## 2. 三个候选设计方向

### 方向 A：情报墙（Evidence Board）

**隐喻**：侦探剧里那面贴满照片、用红线连起来的墙。

- 打开 LUMEN，看到的是一整块**近乎全屏的画布**，文档以"卡片"形式钉在画布上，卡片之间用线连接（关联强弱=线的粗细，这一点和 PRD 里"关联图"的设定一致，区别是**这不是 Phase4 才有的高级功能，而是从第一天就存在的主界面**）。
- 矛盾检测不再是文档下方一条黄色警示框，而是画布上**两张卡片之间凭空出现一条红色的线**，代表"这两份文档在打架"，点击这条线才展开具体冲突内容——把"发现矛盾"这件事从"阅读时的旁注"提升为"画布上一眼可见的异常"。
- 空间切换（`nova-internal` ↔ `brightlite-team`）不是下拉菜单，而是**换一面墙**——像走进另一个房间，墙上钉的东西完全不同。这个隐喻天然解释了"为什么两个空间的知识完全隔离"，比一个下拉框更有记忆点。
- AI 不是一个独立的聊天窗口，而更像**站在墙边帮你整理线索的助手**：你问它问题，它伸手在墙上圈出相关的几张卡片，而不是在旁边弹出一段纯文字回答。
- 术语的"悬浮释义"变成**贴在卡片边上的小便签**，风格上呼应"手写批注"的质感，而不是标准 UI 组件的 tooltip。

**优点**：情感浓度最高，最贴近场景文字的"发现感"；把 Phase4 的高级能力前置成为产品灵魂，而不是加分项。
**代价**：全屏画布对"随手记一笔"这种轻量场景不友好——Lily 在电话会间隙快速记一条纪要时，不会想先在一面墙上找地方钉卡片。需要一个"快速模式"逃生舱。

### 方向 B：星图宇宙（Constellation）

**隐喻**：每个空间是一片星域，主题是星团，文档是星星，时间是纵深。

- 首页是深色背景上的**星群**，越常被引用/关注的文档星星越亮、越大；点击一颗星，周围与之关联的星星亮起连线，像看星座图。
- 时间轴不是横向的表格，而是**穿越星群的一条轨迹**——沿着轨迹飞行，依次经过每个事件节点。
- 视觉冲击力强，"探索感"直接拉满，适合首次打开、无所事事随便逛的场景。

**优点**：视觉记忆点极强，"发现新大陆"式的探索欲望最直接。
**代价**：与场景里"上午十点开电话会""临近中午处理提议"这种高频、日常、略带疲惫感的真实工作节奏不太搭——星图适合"仰望"，不适合"埋头干活"，容易变成华而不实的开场动画，用几次就腻。且深色科幻风格与"BrightLite 智能照明公司、客户张总"这种朴素的中小企业语境有点违和。

### 方向 C：案卷夹（Dossier）

**隐喻**：一份份纸质案卷，贴着标签、盖着章、按项目归档在抽屉里。

- 保留"文件夹"的心智模型（用户已经很熟悉），但每个项目文件夹打开后是一份"案卷封面"——项目名、关键人物头像、时间跨度一览、最近活跃度，而不是干巴巴的文件列表。
- 时间轴做成"翻页式的卷宗"，矛盾提示做成"贴纸式的红色回形针"。
- 保守、低风险、开发成本最低，几乎可以直接套用现有的三栏骨架做视觉包装。

**优点**：风险最低，最容易在保留 PRD 既有结构的前提下改善视觉调性。
**代价**：本质上只是"三栏笔记软件+情报风皮肤"，没有真正回答"LUMEN 的第一眼该是什么"这个问题，前三份参照产品已经证明这条路"能用但不惊艳"。

---

## 3. 推荐方向：情报墙为主画布，案卷抽屉为辅助层

综合权衡后，建议走**方向 A 为主、吸收方向 C 的"快速模式"作为补充**的混合方案，理由：

- LUMEN 与前三款产品最大的差异化机会就在"情报分析"这条线，如果视觉骨架不体现这一点，产品会被用户下意识归类为"又一个知识库/笔记软件"，丧失差异化认知；
- 但场景里同样存在大量"随手记、快速处理"的轻量时刻（场景3 Lily 挂了电话快速补一句纪要；场景8 Lily 睡前补一个日期），这些时刻不能被"盯着墙找地方钉卡片"的重仪式感打断。

**具体建议的骨架**：

```
默认打开：全屏情报墙（当前空间的卡片与关联线）
          ↓ 顶部有一个不起眼但常驻的"快速录入"胶囊按钮
          点击 → 从底部弹出一个轻量抽屉，30秒录入，不打断墙面视野
          ↓ 需要"找文档"而非"看关系"时
          左侧唤出一个可收起的传统列表/目录（作为墙的补充检索工具，而非首屏主角）
          ↓ 需要专注写一篇长文档
          墙上双击某张卡片 → 全屏切入"案卷"式编辑视图，写完关闭，卡片回到墙上原位
```

这样"墙"承担"发现关系、感知全貌"的职责，"抽屉/案卷视图"承担"快速录入、专注写作"的职责，两者不互相打架，而是**同一空间的两种缩放层级**（像地图应用的"卫星视图"和"街景视图"切换，而不是两个割裂的功能模块）。

---

## 4. 几个值得跳出常规的具体交互提案

1. **搜索不是输入框弹结果列表，而是"手电筒"**：在情报墙上敲入关键词，画布整体变暗，只有匹配的卡片保持明亮并微微放大——把"搜索"做成一个在墙上找东西的动作，而不是切换到另一个页面看列表。
2. **矛盾提示可以有"张力感"的动效**：两份数据打架的文档之间那条红线，可以有轻微的抖动/脉冲效果，模拟"这里有问题，需要有人来看一眼"的视觉提醒，比静态的黄色边框更容易被主动发现。
3. **术语像地图上的图例，而不是字典弹窗**：把已确认的术语做成墙面一角的"图例角落"，而不是必须悬停才能看到的隐藏信息——让新人（如 Kira）一进空间就能扫一眼图例大致了解"这里常说的黑话是什么"，呼应场景9里"新人靠标签视图快速建立主题全貌"的诉求。
4. **AI 对话框可以"指物"**：当 AI 回答引用了某几份文档，墙上对应的卡片应该同步高亮/轻微放大，形成"AI 说话的时候，墙在配合它做手势"的联动感，而不是纯文字加一行来源链接。
5. **空间切换用"翻墙"的转场，但要快**：不必做成炫技的3D旋转，一个简单的"当前墙面向左滑出、新墙面从右滑入"即可传达"这是完全不同的一批线索"，同时保证响应速度（PRD 里 3 秒加载上限的约束即使不看 PRD 也是常识底线，值得保留）。

## 5. 视觉调性建议（脱离PRD后的自由发挥）

- **不要走深色科幻风**（排除方向B的视觉语言）——LUMEN 服务的是"中小企业+初创顾问公司"的朴素工作场景，过度炫技的视觉会和"张总""BrightLite 智能照明"这类接地气的角色语境脱节；
- 建议走**"温暖的工作室"调性**：米白/浅木色背景 + 卡片用略带纸张质感的浅色块 + 关联线用手绘感的曲线而非绝对直线，整体像"一个人真的坐在那面墙前工作"，而不是"打开了一个冷冰冰的企业后台系统"；
- 矛盾/术语/同步这几类提示的颜色分级（蓝/橙/黄）建议保留（这是从场景文字里提炼出的、与视觉骨架无关的语义约定，值得继续沿用）；
- 人物元素可以适度保留——场景文字里角色感很强（Alice、Mark、Kira、Lily），如果 AI 助手在界面里能有一点点"人格感"（哪怕只是文案语气而非卡通形象），会比纯工具化的问答框更贴合原始叙事的温度。

## 6. 需要与你一起判断的取舍

- [ ] "情报墙为主画布"对开发成本的影响远高于传统三栏列表，需要确认团队是否有意愿投入做这种非标准骨架，还是先用方向C的低风险方案验证核心功能，视觉留到后续版本再升级。
- [ ] 全屏画布在文档数量达到几百上千份时的可读性/性能问题（不同于前三款产品的分页列表）需要提前设计"聚合/收起"机制，否则墙会变得杂乱不可用。
- [ ] "快速模式"抽屉与"情报墙"之间的开关，是用户主动切换，还是系统根据操作类型自动判断（如检测到只是填个表单就不打开墙），需要进一步定义触发规则。
- [ ] 移动端是否还保留"墙"的隐喻，还是移动端直接退化为方向C的传统列表——小屏幕上大面积可拖拽画布的可用性存疑，需要单独验证。
