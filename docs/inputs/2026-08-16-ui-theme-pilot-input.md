## 4. 主题候选设计输入（起点值，全部待对比度计算校验，不得直接当最终规范）

### A 套：浅色基线精修（对照组）

- **参照**：notion（克制）+ mintlify（代码面固定）。
- **要点**：保持 `#f4f6f9` 基底与 `#2563eb` 主色不动；收敛 `--blue-soft` 类软底的使用面（彩色只留给数据 / 状态标记）；统一 hover 激活信号（学 sanity 的单一激活色纪律）；代码块固定深色面。
- **目的**：参照系，防止 B/C 上线后回不去；顺带完成令牌化清理的主体验证。

### B 套：深色（知识库高频需求）

- **参照**：linear（结构）+ raycast（语义色）+ sanity（纪律）。
- **起点 token 草案**：画布 `#0d0e12` 一档 + 面板阶梯 3 级（如 `#14151a / #1a1c22 / #22242c`）；文字阶梯 4 级；发丝线 `rgba(255,255,255,0.08)`；语义色整体提亮一档并配 12–15% 软底（raycast 配方）；主色沿用 `#2563eb` 提亮变体（如 `#5b8cff`）保持品牌连续性。
- **风险**：markdown.css（15 处）与文档阅读页在深色下最易穿帮；语义绿 / 红在深底上需重校。

### C 套：暖米纸（品格方向，衔接 brief 既有「米白」候选）

- **参照**：claude 主案 + warp（深色版暖炭）。
- **起点 token 草案**：画布 `#faf9f5`；面板 `#ffffff` 或 `#f5f0e8`；墨色暖一档（`#1c1b18` 类）；主色珊瑚 / 赭（`#c96442` 类）；发丝线暖调（`#e8e1d6` 类）。
- **风险**：现有蓝系语义色在暖底上会「发灰」，语义四色需整体重校；这是三套里重校量最大的。

## 6. 评估方案（两层，试点收口时落盘 `docs/research/YYYY-MM-DD-ui-theme-pilot-evaluation.md`）

### 第 1 层：主题交付质量

| 维度 | 方法 | 通过线 |
|---|---|---|
| 可读性 | 对比度计算（工具跑 token 组合） | 每套主题正文 ≥4.5:1、大字 / 组件 ≥3:1，不过即改 |
| 语义色区分度 | 每套主题下 success / warning / error / info + hover / disabled 逐一核对 | 语义不可混 |
| 令牌覆盖率 | 改造前 202 处基线（本文件 §2）vs 改造后 grep 残留 | 残留为 0 或全部入豁免清单 |
| 切换正确性 | 每套主题 × 主要页面（工作区 / 文档详情 / 时间线 / 管理页）截图矩阵 + 刷新持久化 + 无闪烁 | 无残留旧样式 |
| 人工评分 | 截图矩阵 1–5 分（可读性 / 层级 / 协调感），用户 + AI 各评（AI 分仅参考） | 用户拍板方向即通过，分数留档 |

### 第 2 层：机制试点（供母模板知识层复盘，结论不自动回写）

- RA 模板可用性：哪些字段卡壳 / 冗余 / 缺失。
- 模式命中率：引用几条 `PAT-VIS-*`、几条真正影响决策、几条排除及理由。
- D 级封顶规则实效：awesome-design 案例实际起了什么作用；是否出现「想拿 D 级当依据」的压力场景。
- 令牌化路径复用性：「CSS variables 单点 → `[data-theme]` 多主题」是否值得提炼为新 `PAT-VIS-*` 候选（记为回流候选，不在本仓决定）。
