# 立项：LUMEN 前端设计系统规范（frontend-design-system.md）

> 定位：工作流立项记录（research 阶段产物），非设计事实。目标产物为 `docs/design/frontend-design-system.md` + 配套可执行约束 + 回流案例包。用户 2026-08-16 拍板立项；主题试点 PR（feat/ui-theme-pilot）照常先行收口，本工作流在其 merge 后启动。

## 0. 背景与动机

- 主题试点（2026-08-16）验证了「令牌单点 → 多主题」路径，但仅覆盖视觉语言 10 层中的第 1 层（色彩）。用户实测反馈：搜索 / 问答 / 标签 / 时间线 / 成员等页面大量输入栏 / 按钮 / 卡片为白色矩形，与背景对比突兀——暴露「容器与分隔无规则」（第 2 层缺失）。
- 用户期望升级：**LUMEN 要产出一份较为完整、规范的前端详细设计文档，作为可回流母模板的成功案例**；让 AI 在该范围内依据设计与约束生成代码，而不是各写各的。
- 核心认知：防「AI 各写各的」不靠文档写得全，而靠**每个视觉决策点有唯一权威源（token / 规则）+ 违规可被 CI 拦截**。文档三段式（现状实证 → 规则 → token/CI 对照）自带审计痕迹。

## 1. 目标形态（三层）

| 层 | 产物 | 作用 |
|---|---|---|
| 规范文档 | `docs/design/frontend-design-system.md` | 人读的完整描述：基础层 10 项 + 组件契约层 + 模式层 |
| 可执行约束 | `tokens.css` 参数单点（字阶 / 圆角 / 间距 / 投影 / 动效补齐）+ CI 检查扩展（颜色已有，圆角 / 字号白名单候补）+ 规则入 `ai/project-rules.md` §5.1 | AI 生成代码时硬性可查 / 可拦的依据 |

## 2. 规范文档目标结构

```text
frontend-design-system.md
├─ 0 元信息（输入来源 / 适用范围 / 与 brief·frontend-interaction 的关系 / 回流标记）
├─ 1 基础层（10 项，每项三段式：现状实证 → 规则 → token/CI 对照）
│    色彩✅ 分隔❌ 投影⚠️ 字阶❌ 间距⚠️ 圆角❌ 状态❌ 密度✅ 动效⚠️ 图标❌
│    （✅=主题试点已建立  ⚠️=有 token 无纪律  ❌=无规则；状态截至 2026-08-16）
├─ 2 组件契约层（按 8 类：按钮 / 输入 / 列表 / 卡片 / 浮层 / 导航 / 反馈 / 编辑器）
├─ 3 模式层（空态 / 加载 / 错误 / 表单校验 / 行内编辑——衔接 frontend-interaction.md）
├─ 4 治理（token 变更流程、CI 门禁清单、新增组件 checklist）
└─ 5 回流清单（哪些章节可抽象为 PAT-VIS-*，跨仓提案另议）
```

基础层 10 项的判断标准（非凑章节数）：任何人在任何新界面做视觉决策时，都能从文档查到依据，不需要即兴发挥。分层数字本身不是权威（业界 6-15 不等），本项目按 CSS 实际混乱点归纳为 10。

## 3. 分隔与容器策略要点（用户反馈的「满屏白框」问题，第 2 层）

分隔四手段选用规则（待试点验证后成文）：

| 手段 | 何时用 | 对应 token |
|---|---|---|
| 留白 | 同组元素内部 | `--space-*` |
| 分隔线 | 同容器内的列表行 | `--line-soft`（divider 语义待立） |
| 边框 | 真正的容器边界（**一视图一层**） | `--line` |
| 投影 | 浮层（弹窗 / 下拉 / toast） | `--shadow-*` |

配套规则候选：一视图一容器；列表项去框改分隔线；次要按钮幽灵化（透明底 + hover 洗色）；输入框保留淡边（可用性）；浮层才投影。

## 5. 边界

- 本工作流只管前端视觉语言与组件呈现；不改信息架构 / 交互流（frontend-interaction.md 权威不动）、不新增 REQ / 接口 / 验收目标。
- 图标层（第 10 项）工程量大，列为可选末位，试点后按投入产出再定。
- 回流母模板属跨仓决策：本仓只产材料（规范 + 证据链 + PAT-VIS 候选清单），提案与合并由母模板侧决定。
- 设计事实以最终 `frontend-design-system.md` 为准；本立项记录只记录目标与路径，不预设结论。
