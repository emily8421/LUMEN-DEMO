# 视觉语言审计：10 层现状实证与 gap 表（设计系统工作流步骤 1）

> 定位：`docs/research/2026-08-16-frontend-design-system-charter.md` 路径步骤 1 产物。基于 v3.9.0（main `2aca014`）全量 CSS 实证扫描（28 个组件 CSS + tokens.css + TSX 抽查），产出规范文档 §1「基础层」的现状素材。**只记录实证与 gap，不预设规则**——规则在步骤 2（结构 RA）提炼配方、步骤 4（两页试点）验证后成文。

## 0. 审计方法

- 统计口径：`frontend/src/styles/*.css` 除 tokens.css 外全文正则扫描；图标层补 TSX 扫描。数据截至 2026-08-16。
- 分层框架：charter §2 基础层 10 项；每项给「现状实证 → 问题定性 → 可参数化程度」。

## 1. 十层现状与 gap

### ① 色彩 —— ✅ 已建立（v3.9.0）

四套主题 token 单点（light/dark/paper/legacy）+ CI 守门（check:css）+ WCAG 对比度校验链。**唯一完整闭环的层**。剩余 gap：无（后续主题迭代走「新增主题三步法」brief §3.1.1）。

### ② 分隔与容器 —— ❌ 无规则（「满屏白框」根因，用户实测反馈）

| 实证 | 数据 |
|---|---|
| 全边框 `border: 1px solid` | **65 处**（每个列表项/卡片/输入框/按钮各一圈） |
| 单侧分隔线 | 39 处（多为 pane 边界，用法正确） |
| 虚线框 dashed | 3 处（drop-zone 等） |
| `--line` vs `--line-soft` 使用比 | 73 : 36（强线使用占 2/3，弱分隔线未成主力） |

问题定性：四种分隔手段（留白/分隔线/边框/投影）无选用规则，几乎所有元素选了「边框」；「一视图一容器」原则缺失——搜索/问答/标签/时间线/成员页的列表项、次要按钮、输入框全部自带框。**改造收益最大的层。**

### ③ 投影 —— ⚠️ 半建立

7 档 token 全走 var()（sm/md/lg/xl/drawer/accent/card ✓）；gap：**无分级选用规则**（什么时候 card 档 vs sm 档无依据），且 65 处边框与 13 处投影并存——边框去框化后投影体系需接棒定义浮层层级。

### ④ 字阶 —— ❌ 无阶梯

| 实证 | 数据 |
|---|---|
| 字号 | **22 种值**：12px×60、13px×26、11px×15、14px×8、10px×7、16px×6、15px×5、12.5px×5 + 长尾（0.72/0.75/0.8/0.85/0.9rem、11.5px、13.5px、17/18/20/22/26px、0.92em、1.25rem） |
| 字重 | 6 种：600×13、700×6、800×5、500×2、650×1（**650 非标准档**） |
| 单位 | px 为主 + rem/em 混用 9 处（rem 基准未定义，换算不可控） |

问题定性：无语义字阶（caption/body/secondary/title 之类），22 种字号实为同 5-6 个意图的随意取值；650 是 Inter 可变字重时代遗留。可参数化：定义 4-5 档语义 token 后，22 种值可收敛到 6 以内。

### ⑤ 间距 —— ⚠️ 有 token 无纪律

`--space-1..4` 存在且 gap 使用率高（space-2×39、space-3×17、space-1×6）；但 padding 字面值大量绕行（`2px 8px`×6、`6px 10px`×4、`6px 12px`×3……前 15 名里字面值占 12 席），gap 也混用 `2px×17、4px×14、6px×13、5px×3` 字面。gap：**4px 网格纪律未成文**，半数间距绕过 token。

### ⑥ 圆角 —— ⚠️ 有 token 无纪律

`--radius-control`×22 + `--radius-panel`×20（占主导，好）；但字面值 **9 种**：4px×17、999px×12（胶囊，可豁免）、6px×5、2px×4、8px×4、3px×3、5px×3、10px、12px——4px 与 6px 与 `--radius-control`（6px）语义重叠。gap：两档 token 覆盖不了现状（微元素 2-4px / 控件 6px / 卡片 8px / 浮层 10-12px 实为 4 个意图）。

### ⑦ 状态表达 —— ❌ 不一致

hover 表达实证（14 处抽样）：主按钮变 `--accent-strong` ✓ 统一；但次要元素 hover 分四路——`--panel-soft` 底、`--blue-soft` 底、仅文字变 `--blue`、仅 underline；active 激活又是另一套（`--blue-soft`+border 或 border-left 3px 蓝）。focus 表达：全局 `--focus-ring`✓，但 **9 处 `outline: none`**（抽查：6 处有 `:focus-visible` 补偿 ✓，3 处无补偿——resizer/toolbar-btn，键盘可达性缺口）。gap：sanity 式「单一激活信号」未落地；focus 消除无统一守门。

### ⑧ 密度 —— ✅ 方向已定（brief §3.2 高密度）

列表行高/工具栏尺寸基本一致（min-height 22-28px 区间）；gap：行高 11 种值（1/1.15/1.2/1.25/1.4/1.42/1.45/1.48/1.5/1.6/18px）应收敛到 3 档（紧凑控件 1.2 / 正文 1.5 / 长文 1.7 类）。

### ⑨ 动效 —— ⚠️ 无规范

transition 仅 6 处，但时长取值 0.1s/0.12s 混用、缓动 ease 为主；无进出场/抽屉滑动的时长规范。量小，**改造代价最低的层**（定 2 档：0.12s 交互反馈 / 0.2s 容器）。

### ⑩ 图标 —— ❌ 两体系混用

emoji（5 文件：MarkdownToolbar / LocalMountHeader / LocalMountTreeView / CommandPalette / WelcomeFeature）与 inline SVG（5 文件：FolderTreeHeader / PaneToggles / PaneEdgeToggle / CommandPalette / GlobalSearchBar）并存，**CommandPalette 同时用两套**。gap：无图标族决策（统一 lucide 类线性 SVG / 维持 emoji 的成本权衡）——工程量大，按 charter 列为可选末位。

## 3. 可直接固化的实证结论（步骤 2/3 输入）

1. 「一视图一容器 + 分隔四手段」是 ② 的目标规则形态（charter §3 已预写，试点验证）。
2. 字阶/圆角/间距/行高四项**纯参数化**，可一次令牌升级收敛：字阶 5 档 / 圆角 4 档 / 行高 3 档 / 间距补齐 4px 网格豁免清单。
3. focus 可达性 3 处无补偿 `outline:none` 是**缺陷级**发现（resizer×2、editor toolbar-btn×1），无论规范与否都该修。
4. 650 字重为历史遗留，收敛到 600/700 两档。
5. 单位纪律：px 为主体系，9 处 rem/em 统一（rem 需先定基准，em 仅保留相对场景如行内代码 0.92em）。
