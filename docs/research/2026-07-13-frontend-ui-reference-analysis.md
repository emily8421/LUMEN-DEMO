## 2. LUMEN 自身定位约束

LUMEN 不是单纯个人笔记软件、纯图谱 Wiki 或通用聊天助手。结合既有文档，建议定位为：

> 面向团队 / 客户空间隔离场景的 AI 原生知识工作台：以文档沉淀为底座，以空间 / 权限 / 术语为上下文，以搜索与 RAG 问答为主入口之一，以来源可追溯和演示稳定为核心体验。

现有约束：

- Phase1 Demo 核心闭环是“导入 → 检索 → 问答带来源 → 编辑留版本 → 术语对齐”。
- P1 只承诺桌面端 Demo，可降级处理真实 PDF / Word / OCR，不做移动端。
- P2 才考虑标签、内部链接、AI 润色、快速录入、PDF 导出、时间轴 / 图谱等更完整 MVP 能力。
- 权限边界必须以后端为空间 / 文档权限执行，前端只做可见性和提示辅助。

## 4. LUMEN 交互体验需求建议

### UX-001：团队知识工作台定位

LUMEN 前端应呈现为“团队知识工作台”，不是传统个人笔记软件、纯聊天页、纯图谱 Wiki 或营销型 Demo 页面。界面围绕空间、文档、搜索、问答、术语五类上下文组织。

### UX-002：空间上下文始终可见

当前空间、当前用户、权限边界必须在顶层或核心操作区可感知。空间切换后，文档、搜索、问答、术语都必须随空间刷新，避免跨空间误读。

### UX-003：主信息架构采用工作台 Shell

建议维持 TopBar + Nav Rail + Context Pane + Workspace。Nav Rail 承载一级任务；Context Pane 随视图呈现文档列表、术语列表或轻量筛选；Workspace 承载当前任务主操作。

### UX-004：文档流参考三栏笔记工具，但保持 Markdown / 团队知识库边界

文档视图应保留“列表 → 当前文档 → 编辑 / 预览 / 版本”的稳定路径。P1 不引入完整富文本工具栏或传统桌面菜单；P2 可评估标签、结构化标注和更强编辑辅助。

### UX-005：AI 问答参考“基于知识库问答”，但必须来源可追溯

问答入口应明确限定当前空间可见内容；可提供推荐问题 / 示例问题；答案必须带来源，来源可打开文档。库外问题应明确未找到，不编造。

### UX-006：搜索与问答是一级主任务

搜索和问答不应被压缩在小右栏中，应作为独立 Workspace 占据主工作区。文档列表和版本面板只在相关任务中出现，避免无关上下文抢占屏幕。

### UX-007：术语是团队语义上下文

术语管理不是普通配置表单，应与文档阅读、编辑和问答解释产生联系。P1 保持术语列表 + 编辑 + 问答使用；P2 可增强术语提示、冲突提示和引用解释。

### UX-008：高密度生产力工具风格

LUMEN 不采用大卡片、大留白的展示页风格。建议使用高信息密度、低视觉噪声、列表行 / 工具栏 / Inspector 分层。量化目标可延续：搜索首屏 ≥5 条结果、术语首屏 ≥8 条、编辑区 ≥12 行、900px 桌面宽度无全局横向滚动。

### UX-009：图谱 / 时间轴 / 标签作为 P2 探索型导航

Wiki 材料中的气泡图谱、时间轴、标签聚合适合知识发现，但不进入 P1。P1 先保证文档、搜索、问答、术语闭环；P2 再根据 Phase2 范围决定标签、反链、时间轴或图谱。

### UX-010：降级、权限、空态、错误态必须可见

OCR / PDF 等未真实化能力必须明确降级提示；无权限、空结果、库外问题、导入失败等都要有清晰反馈。前端隐藏入口不能替代后端权限。
