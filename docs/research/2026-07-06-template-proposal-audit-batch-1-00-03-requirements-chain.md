## 2. 总体结论

`docs/00-03` 已能支撑 Phase1 文档链基本运转，具备场景、U-ID、REQ-ID、Phase 路线图和 REQ 覆盖矩阵。但从模板复用角度看，当前规范仍需要进一步细化，以减少派生项目出现以下问题：

1. 场景有叙事，但来源锚点、边界和下游影响不足。
2. 用户需求有 U-ID，但用户操作流、用户验收口径和追溯矩阵不足。
3. SRS 有功能 REQ，但 NFR、约束假设、异常 / 边界场景不足。
4. PRD 有路线图，但 Phase 总览、进入 / 退出标准、取舍依据和非目标追溯不足。
5. `00-03` 的状态枚举、阶段标签和待确认项结构需要统一，便于后续设计、编码和验收使用。

结论：需要独立模板提案 P-01，当前已起草为 `_proposals/TEMPLATE-UPGRADE-00-03-requirements-chain-standard.md`。

## 3. 逐文档观察

### 3.1 `docs/00-scenario.md`

已满足：

- 有背景、目标用户、典型场景和关联文档。
- 能说明产品愿景文档不直接驱动开发，当前阶段由 `03` 与 `project-rules` 决定。

模板缺口：

- 规范应更明确要求“场景边界与非目标”，避免 `00` 中的愿景叙事被直接扩展成需求。
- 规范应要求“上游来源映射”，把每个场景映射到输入材料、愿景段落或人工确认。
- 规范应要求“下游影响”，至少说明场景将驱动哪些 U-ID，变更后应检查哪些 `01-03` 内容。
- 规范应建议稳定 `SCN-ID`，便于后续 `U-ID` 回链。

建议写入 P-01：

- 增加 `场景 ID / 角色 / 触发条件 / 用户目标 / 成功结果 / 来源锚点 / 下游 U-ID` 表。
- 增加 `场景边界与非目标` 表。
- 增加 `来源映射` 表。

### 3.2 `docs/01-user-requirements.md`

已满足：

- 有 P1 / P2 / 愿景分组。
- 每条需求有 U-ID、功能、说明、来源和状态。
- P2 / 愿景保留骨架，未强行写入当前 Phase。

模板缺口：

- 规范应允许阶段分组，但不应因此省略“用户需求总览 / 追溯矩阵”。
- 规范应要求用户操作流，避免 01 退化为功能列表。
- 规范应要求用户可观察验收口径，区别于 02 / 09 的系统测试口径。
- 规范应要求优先级建议与理由，但明确最终 Phase 归属以 `03` 为准。
- 规范应要求非目标与排除需求独立记录，并追踪是否进入 `03` 非目标。

建议写入 P-01：

- 增加 `U-ID / 用户 / 角色 / 用户需求 / 来源场景 / 用户价值 / 初步优先级 / 建议阶段 / 状态` 总览表。
- 增加 `Flow-xxx` 用户操作流模板。
- 增加 `U-ID → 用户验收口径 → 不满足示例` 表。
- 增加 `OUT-ID` 非目标 / 排除需求表。

### 3.3 `docs/02-srs.md`

已满足：

- P1 功能 REQ 可验证，且有 U-ID → REQ-ID 追溯矩阵。
- P2 / 愿景 REQ 保持粗粒度，未作为当前 Phase 必做项。

模板缺口：

- 规范应明确 SRS 不能只写功能需求，还需要 NFR。
- 规范应要求约束与假设，包括资源、合规、权限、数据、外部服务、Mock / 降级等。
- 规范应要求异常 / 边界场景，例如无权限、无数据、导入失败、外部服务不可用、资源不足、跨空间访问、库外问题。
- 规范应要求 SRS 标出下游验证入口，方便 `09` 创建 TC。

建议写入 P-01：

- 增加 `NFR-ID` 表。
- 增加 `CON-ID` 约束 / 假设表。
- 增加 `CASE-ID` 边界 / 异常场景表。
- 增加 `REQ-ID → 验证入口` 字段或独立章节。

### 3.4 `docs/03-prd.md`

已满足：

- 有功能范围、优先级、阶段路线图、REQ 覆盖矩阵和非目标。
- Phase1 同时声明功能范围 `[P1]` 与交付物形态 Demo。
- 后续 Phase 和愿景未进入当前阶段。

模板缺口：

- 规范应要求 Phase 总览表，集中展示功能范围、交付物形态、状态、包含 REQ、进入标准、退出标准和明确不做。
- 规范应要求优先级与取舍理由，而不只是 P1 / P2 / 愿景分组。
- 规范应要求非目标可追溯到 01 / 02 或人工确认来源。
- 规范应要求 `03` 明确影响 `ai/project-rules.md` 当前阶段指针。
- 规范应要求进入 / 退出标准，便于 Phase 升级评估。

建议写入 P-01：

- 增加 `Phase 总览表`。
- 增加 `REQ-ID / 优先级 / 所属 Phase / 取舍理由 / 依赖风险 / 是否阻塞当前 Phase` 表。
- 增加 `OUT-ID` 非目标追溯表。
- 增加 `进入 / 退出标准` 章节。

## 6. 提案拆分判断

本 Batch 建议只起草一个提案：

```text
_proposals/TEMPLATE-UPGRADE-00-03-requirements-chain-standard.md
```

原因：

- `00-03` 是连续需求链，单独拆成 4 个提案会重复讨论来源、追溯、状态和 Phase 边界。
- 一个 P-01 提案可以完整描述 `Scenario → U-ID → REQ-ID → Phase` 的闭环。
- `04-09` 和 `docs/design/*` 的提案会依赖 P-01 输出，不应混入本提案。
