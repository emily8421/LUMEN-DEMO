## 1. 探索目的

### 1.1 需要通过原型确认的问题

1. **分层信息架构是否成立**：空间 → 项目 / 主题 → 子目录 → 叶子文件夹 → 单篇文档的层级，是否能解释大规模文档场景。
2. **经典 / 探索双模式是否必要**：经典目录树 / 列表是否应始终可达，探索模式是否只作为可选增强。
3. **局部情报墙是否比全空间情报墙更合理**：关系图是否只在边界清晰、节点规模可控的局部集合中出现。
4. **数字原生配色是否优于实体公告板风格**：明亮蓝白基底 + 现代靛蓝点缀 + 清晰徽章，是否更符合“AI 情报分析工具”的长期调性。
5. **Phase2 入口是否应先做“空间总览 / 发现层 Lite”**：是否值得在 UI Brief 中把它作为 Phase2 候选方向。

### 1.2 本次原型不确认的问题

- 不确认正式 Phase2 范围，不新增 REQ 或验收目标。
- 不确认图谱算法、矛盾检测、证据地图、路径推理等愿景 AI 能力。
- 不确认具体前端组件库、路由方案、状态管理方案或 CSS 实现。
- 不确认真实指标计算方式，例如活跃度、冲突数量、瓦片大小或颜色映射。

## 3. 原型形式选项对比

| 选项 | 形式 | 优点 | 风险 / 成本 | AI 推荐 |
|---|---|---|---|---|
| A | Markdown 低保真线框 + 表格说明 | 最快、可直接评审信息架构，不引入工具或代码 | 视觉感较弱，配色只能文字说明 | **本轮采用** |

本轮先采用 **A：Markdown 低保真线框 + 表格说明**。若用户认可方向，再输出 `docs/research/2026-07-13-ui-prototype-exploration-prototype.html` 或进入 `docs/design/frontend-experience-brief.md`。

## 6. 主流程草案

### 6.1 Flow A：空间总览 → 项目 → 叶子文档列表

```text
用户进入 brightlite-team
  → 看到空间总览：智慧园区照明 / 客户沟通存档 / 竞品与市场 / 归档其他
  → 点击“智慧园区照明”
  → 面包屑变为 brightlite-team › 智慧园区照明
  → 看到子目录：接口与协议方案 / 现场勘察 / 测试报告 / 客户沟通
  → 点击“接口与协议方案”
  → 进入叶子文件夹文档列表
```

待确认点：项目 / 主题瓦片是否足以替代全空间文档图谱作为默认空间首页。

### 6.2 Flow B：叶子文件夹 → 局部关系图 → 单篇文档

```text
用户在叶子文件夹文档列表中
  → 文档数 28，系统显示“以关系图查看”按钮
  → 用户点击
  → 进入局部关系图：核心方案、测试记录、客户纪要、术语定义形成少量节点
  → 点击某节点
  → 打开同一套单篇文档预览 / 编辑器
```

待确认点：关系图入口是否只在节点数量 / 筛选条件满足时出现；阈值是否采用 25～30 / 30～80 / 80+ 的经验规则。

### 6.3 Flow C：大文件夹自动降级

```text
用户进入“客户沟通存档”叶子文件夹
  → 文档数 126
  → 默认显示传统列表 / 表格
  → “以关系图查看”按钮变为“先筛选后查看关系图”
  → 用户选择“最近 30 天 + 含待核实问题”
  → 结果缩小到 18 份
  → 系统允许生成局部关系图
```

待确认点：自动降级提示是否会被用户理解为限制，还是能被理解为“避免图谱噪点”的帮助。

### 6.4 Flow D：经典模式逃生舱

```text
用户在探索模式的瓦片 / 局部关系图中迷路
  → 点击左侧“目录树”按钮
  → 弹出 / 展开经典目录树
  → 直接跳转到任意项目、子目录或文档
  → 当前模式偏好保留，但经典路径始终可达
```

待确认点：经典目录树应常驻、抽屉式呼出，还是只在顶部按钮展开。

## 8. 关键状态与反馈

| 页面 / 流程 | 状态 | 用户可见表现 | 待确认点 |
|---|---|---|---|
| 空间总览 | 空空间 | 显示创建 / 导入入口，说明当前空间暂无项目或主题 | 空间总览是否允许用户新建项目 / 主题 |
| 空间总览 | 有待核实问题 | 瓦片角标显示“3 待核实”，不直接断言“3 个矛盾” | “待核实”是否比“冲突 / 矛盾”更安全 |
| 层级下钻 | 深层目录 | 面包屑始终常驻，目录树可呼出 | 面包屑最大显示层级和省略规则 |
| 叶子列表 | 文档数 80+ | 默认列表，关系图入口提示先筛选 | 阈值是否需要配置化 |
| 局部关系图 | 关系来源不确定 | 边 / 节点标记“候选关系 / 待确认” | 候选关系是否需要人工确认入口 |
| 单篇文档 | 无权限 | 显示“无权限或资源不存在”，不泄露标题 | 沿用 P1 权限口径 |
| 问答 | 无来源 | 显示“未在当前空间知识库找到” | 沿用 P1 产品红线 |

## 9. 文案、信息密度与可理解性

### 9.1 用户需要一眼看到的信息

- 当前空间名、当前层级面包屑、当前模式（经典 / 探索）。
- 项目 / 主题数量、每个瓦片的文档量、最近更新时间、待核实数量。
- 叶子文件夹下文档列表的标题、类型、更新时间、状态、权限 / 降级提示。
- 局部关系图中的选中节点详情和返回列表入口。

### 9.2 容易误解的表达

- “矛盾 / 冲突”容易被误解为系统已判断事实冲突；探索阶段建议使用“待核实问题”。
- 瓦片颜色 / 大小容易被误解为严格指标；必须有图例或 hover 说明。
- 关系线容易被误解为确定关系；建议标明“候选关系 / 来源于链接 / 来源于共同标签 / 来源于 AI 建议”。
- “探索模式”不应暗示比经典模式更高级；它只是另一种视角。

## 12. 建议回填与下一步

### 12.1 建议回填路径

1. 用户审阅本文 §5～§11，确认是否认可分层空间总览、经典 / 探索双模式、局部情报墙和数字原生配色方向。
2. 若用户确认部分方向或需要先沉淀阶段性收敛结论，新增 / 更新 `docs/design/frontend-experience-brief.md`，并明确区分候选、待确认与已确认体验原则。
3. 再把已确认或候选内容最小回填到 `docs/design/frontend-interaction.md` 的 Phase2 / 愿景骨架；未确认内容不得写成正式页面 / Flow / TC。
4. 若 Phase2 排期，再更新 `docs/08-dev-plan.md` 与 `docs/09-verification.md`，新增验收目标。
5. 若仍需视觉确认，再生成静态 HTML 原型作为 UI 评审辅助材料；该 HTML 仍属于 research / prototype，不等于实现。
