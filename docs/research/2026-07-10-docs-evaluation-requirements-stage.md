## 4. 问题项

### P0-1：`02-srs` 与 `03-prd` 对 `REQ-009/010` 的 Phase1 验收口径冲突

**现象**

- `docs/02-srs.md` 仍把 `REQ-009` 写成真实 `.docx / .pdf` 上传解析，并以导入 `.pdf` 后可搜可问答为验收。
- `docs/02-srs.md` 仍把 `REQ-010` 写成上传图片 / 白板照片并 OCR 提取文字。
- `docs/03-prd.md` 已明确 Phase1 Demo 只按 `.md / .txt` 已提取文本降级演示，真实 Word / PDF 解析与 OCR 不作为 Phase1 Demo 退出阻塞。

**影响**

- 严格按 SRS 看，Phase1 会被误判为未完成真实 PDF / OCR。
- 严格按 PRD / Verification 看，Phase1 已完成 Conditional Go。
- 同一需求链存在裁决冲突，会影响 Phase1 closure 和 Phase2 进入评估。

**修改建议**

- 将 `REQ-009` 修改为 Phase1 Demo 支持 `.md / .txt` 已提取文本导入；真实 `.docx / .pdf` 解析留后续真实化。
- 将 `REQ-010` 修改为 Phase1 Demo 以 OCR 预提取文本替代；真实图片 / 白板 OCR 留后续阶段。
- 在 `REQ-009/010` 验收口径中明确“真实 Word / PDF / OCR 不作为 Phase1 必过”。

### P1-4：`REQ-007 / U-07` 未反映 task-009 后的 hybrid search

**现象**

- `01` 仍写“按关键词检索文档”。
- `02` 仍写“按关键词返回匹配文档”。
- `09` 已记录 `/api/search` 升级为 substring + `ts_vector` SQL 候选 + pgvector 语义召回。

**影响**

- 当前实现能力超过需求文本，严格审计时可能被判为需求未授权增强。

**修改建议**

- 将 `U-07` 改为“全文 / 语义搜索”：按关键词或语义相关问题检索文档。
- 将 `REQ-007` 改为“按关键词或语义相关查询返回当前空间可见文档，结果含标题 / 摘要 / 定位；语义召回基于已生成 embedding，zhparser 中文分词为可选增强”。
- 验收改为“搜索已知关键词或语义相近问题能返回正确文档；不得返回无权限文档”。
