# Batch 5 审计报告：`docs/design/*` 通用详细设计模板规范

> 定位：本报告是 Batch 5（`docs/design/*` 通用详细设计）的只读审计与 P-06 提案依据，不替代任何 `docs/design/*` 正式修订。
> 评估日期：2026-07-06
> 上游总览报告：`docs/research/2026-07-06-docs-system-template-proposal-audit.md`
> 对应提案：`_proposals/TEMPLATE-UPGRADE-design-doc-standard.md`

## 1. 审计范围

本 Batch 聚焦非编号详细设计文档：

| 文档 | 设计主题 |
|---|---|
| `docs/design/frontend-interaction.md` | 前端交互与桌面端界面 |
| `docs/design/ingestion.md` | 内容导入子系统 |
| `docs/design/intelligence-analysis.md` | 情报分析愿景子系统 |
| `docs/design/permissions.md` | 空间与权限子系统 |
| `docs/design/rag-retrieval.md` | 检索问答子系统 |
| `docs/design/term-management.md` | 术语管理子系统 |
| `ai/doc-standards/README.md` | 当前只提供 `docs/design/*` 待确认项基线与前端交互设计基线 |
| `ai/document-lifecycle-rules.md` | 详细设计、前端交互触发、图表、追溯与禁止项规则 |

本报告只判断可回流模板规范缺口，不直接修订项目事实文档。

## 2. 总体结论

当前项目的 `docs/design/*` 已覆盖多个非平凡子系统，并普遍具备职责、流程、关键决策、阶段增量和跨子系统交互。但模板层面目前只有前端交互设计基线和待确认项基线，缺少通用 `docs/design/*` 详细设计标准，导致不同设计文档结构差异较大。

结论：需要独立模板提案 P-06，建议新增 / 强化 `docs/design/*` 通用规范，文件名为 `_proposals/TEMPLATE-UPGRADE-design-doc-standard.md`。

## 3. 逐文档观察

### 3.1 `docs/design/frontend-interaction.md`

已满足：

- 明确承接 `03/04/05/07/08/09`，声明不新增需求、接口、权限规则或验收目标。
- 有页面信息架构、页面清单、核心用户流、状态 / 空态 / 错误态、权限可见性、桌面端适配、追溯矩阵和阶段增量。
- 明确前端隐藏入口不替代后端权限边界。

模板缺口：

- 通用 design 标准应要求所有详细设计都有 `0. 文档元信息`，包括输入来源、覆盖 REQ、关联 04/05/06/07/08/09、状态和最后更新。
- 应要求“实现对齐 / 偏差记录”字段，避免设计存在导入面板等页面能力，而实现 / smoke 尚未具备时缺少记录位置。
- 待确认项应使用结构化表格，而不是自由文本列表。

### 3.2 `docs/design/ingestion.md`

已满足：

- 明确对应 REQ-009 / REQ-010，承接 04、06。
- 有 P1 流程图和关键决策。
- 有失败处理和阶段增量。

模板缺口：

- 详细设计模板应要求 Mock / 降级口径，特别是 OCR、外部服务、Embedding、异步任务等能力。
- 应要求状态机 / 任务状态表，明确 `processing / done / failed` 等状态含义。
- 应要求资源约束和技术环境评估引用。
- 应要求与 07 API 契约、06 DB 状态字段、09 TC 的追溯。

### 3.3 `docs/design/intelligence-analysis.md`

已满足：

- 明确为愿景骨架，不进入当前 Phase。
- 标出高风险 AI 能力和待技术验证要求。
- 有愿景功能表与图示。

模板缺口：

- 通用 design 标准应支持“愿景 / 高风险能力骨架”模式，要求 readiness gate、Spike / PoC 条件和进入 Phase 前置条件。
- 应要求“不提前实现 / 不作为当前验收”的显式声明。
- 应要求风险项与 05 技术风险、09 后续验证项的映射。

### 3.4 `docs/design/permissions.md`

已满足：

- 明确对应 REQ-001 / 002 / 003。
- 有模型、过滤点、权限流程图、关键决策和阶段增量。
- 明确过滤下沉，不依赖应用层事后裁剪。

模板缺口：

- 权限类详细设计应要求角色 × 动作矩阵。
- 应要求负向用例和泄露边界，例如不可泄露资源是否存在。
- 应要求审计 / 日志 / 安全测试追溯。
- 应要求 DB 查询、API 权限、前端可见性之间的边界映射。

### 3.5 `docs/design/rag-retrieval.md`

已满足：

- 明确搜索 / RAG 流程、权限过滤、来源标注、无候选块不编造和 LLM 失败降级。
- 有流程图、关键决策、失败 / 边界、阶段增量和子系统交互。

模板缺口：

- AI / RAG 类详细设计应要求检索参数、评分 / 排序、Prompt 合同、来源引用合同、质量评估指标。
- 应要求 Mock / 降级与真实 LLM / Embedding 能力的差异说明。
- 应要求安全边界：不得发送敏感片段到外部模型、不得回答库外内容、不得引用不可见来源。
- 应要求与 09 评估用例 / golden dataset / smoke 问题集的映射。

### 3.6 `docs/design/term-management.md`

已满足：

- 明确对应 REQ-036，承接 04、06、07。
- 有术语维护、文档术语识别、RAG 问答口径对齐流程。
- 有空间优先、状态不阻断、轻量匹配等关键决策。

模板缺口：

- 通用 design 标准应要求状态机 / 状态枚举，明确 `confirmed / pending` 等状态含义。
- 应要求冲突规则、同名优先级、权限动作和 API / DB 字段对齐。
- 应要求 UI、RAG、文档编辑等多入口一致性检查。
- 应要求关联 TC / 验收路径。

## 4. 可回流模板缺口

| 缺口 ID | 缺口 | 影响 | 建议提案内容 |
|---|---|---|---|
| B5-GAP-001 | 缺少通用 `docs/design/*` 标准文件 | 不同详细设计结构不一致，审计困难 | 新增通用 design 文档结构与字段 |
| B5-GAP-002 | design 文档缺少统一元信息 | 输入来源、覆盖 REQ、状态、下游影响不稳定 | 增加 `0. 文档元信息` 模板 |

| B5-GAP-008 | 待确认项容易退化为自由文本 | AI 建议、依据、取舍和阻塞关系不清 | 继续强化结构化待确认项 |

## 6. 提案拆分判断

本 Batch 建议只起草一个提案：

```text
_proposals/TEMPLATE-UPGRADE-design-doc-standard.md
```

原因：

- 当前缺口是 `docs/design/*` 通用结构不足，不宜按每个子系统拆多个提案。
- UI、权限、AI/RAG、导入、术语和高风险愿景可先作为通用 design 标准中的分类 checklist。
- Mock / 降级和权限 / 安全可能跨多个文档，是否独立拆 P-07 / P-08 应在 Batch 6 去重收口时判断。
