## 1. 总体结论

- **文档骨架与追溯链完备度：高。** `00-09 + design/*` 的 REQ 覆盖、阶段标签、契约门禁、验证留痕均超出通用方法论要求；不是一份「缺内容的体系」。
- **核心偏差一（缺 OO 图纸）**：LUMEN 是「表格 + 矩阵 + 少量流程图」驱动的体系，非 OO 图纸驱动。对照参考方法论，**用例图、分析类图 / 领域模型、概设类图、详细类图全部缺失**，交互图与活动 / 状态图仅零星覆盖。这是系统性缺口。
- **核心偏差二（阶段错置）**：`03` §3/§4 与 `04` §5.1/§5.4/§1.3 混入了大量应属详细设计（06/07/design）甚至实现（08/09/CHANGELOG）级的实现事实，违反 `03 standard §1`（不写架构 / 接口字段 / DB 表 / Sprint 细节）与 `04 standard §1`（不写表字段 / 接口字段 / Sprint 实施步骤）。
- **成因**：2026-07 起多轮「代码事实反向同步」有意回填（REQ 状态单点索引即其产物），是便利性选择，但偏离 doc-standards 定位。
- **本报告不直接修改需求 / 设计事实。** 下方修改建议通过正式文档修订落回 `docs/00-03` / `04` / `06`，并去项目化回流模板。

## 4. 缺口清单（缺图纸 / 缺章节）

### G1【P0】用例图缺失——需求分析层无 OO 建模

全仓（含 `ai/`）无任何 `useCase` / 用例建模。参考方法论把用例图列为基础阶段核心产出，是「边界用例、内部用例、参与者交互」的可视锚点。LUMEN 00-03 只有表格式 REQ 清单，`REQ → F-ID → Phase → AC/TC` 可追溯但不可视、不可按用例评审边界。

> 建议：在 `00-scenario.md` 补 1 张**全景用例图**（mermaid `flowchart`：角色 + 用例域，挂 REQ 追溯，图 ID `DIAG-UC-01`）。不新增需求，只把既有 REQ 的用例视图可视化。

### G2【P0】领域模型（分析类图）缺失

参考方法论需求分析阶段由 E-E 表 / ERD 抽「实体 = 类、联系 = 方法、属性 = 属性」形成分析类图。LUMEN 实体关系只在 `06 §4` ERD（物理表级）出现，**没有需求级概念 / 领域模型**。实体概念（文档、空间、权限、标签、术语、版本、会话…）在 02/03 无统一定义点，直接落到物理表。

> 建议：`06-db-design.md` 新增 §0.5「概念模型」，mermaid `classDiagram`（核心实体 + 关联 + 关键属性，不含字段级约束，图 ID `DIAG-DOM-01`），作为物理表的概念上游。

### G3【P1】概设 / 详设类图缺失

参考方法论概要设计产出概设类图（类与交互、补属性方法），详细设计产出详细类图（内部逻辑、方法签名 / 参数 / 算法）。LUMEN 用 MOD 表 + 06 表结构 + 07 接口矩阵替代，但缺对象级视图。

> 建议（可选增量）：对核心子系统（权限、导入、RAG、账户）补 `classDiagram`，图 ID `DIAG-CLS-<MOD>-01`。增强项，不阻塞当前维护态。

### G4【P1】概要级交互图覆盖不足

参考方法论概要设计要交互图。LUMEN 概要级只有 `04 §5.1` 一个 Flow-001 顺序图；其余流程在 `07 §3.8`（详设级）。概要设计层的「核心用例 → 对象交互」视图基本缺失。

> 建议：为 `04 §5` 关键流程（Flow-002 统一过滤、Flow-005 AI 润色、Flow-010 Vault、Phase2D 认证升级）补概要级顺序图，粒度到「角色 / 子系统 → 子系统」消息，**不写具体 endpoint 路径**（见 M2）。

### G5【P1】事物-事件表（E-E 表）缺失

参考方法论需求获取阶段产出 E-E 表（主谓宾抽取事物 / 事件 / 属性）。LUMEN 完全没有。考虑到需求已定稿、进入维护态，此为历史遗留方法环节，**建议不回补**，仅记录为方法论偏差；日后新需求获取按 E-E 方法走。

### G6【P1】概要设计的「出错处理设计」「系统数据结构设计」章节缺失

参考方法论把**出错处理设计**和**系统数据结构设计**列为概要设计规格说明书的组成部分。LUMEN：
- 错误码分散在 `05 §5.2` / `07 §3.4` / 各 design——**无概要级统一出错处理策略**。
- 概要级数据结构设计无（全在 06 字段级）。

> 建议：`04` 补一节「出错处理与权限拒绝设计」——把 4001/4003/4030/4090/5030 错误码族的**分层与传播原则**（api 层转 HTTP、service 抛领域异常、错误 msg 固定文案）在概要级固化为架构事实，细颗粒留 07。数据结构设计由 G2 概念模型承接。

### G7【P2】实现阶段「类代码规格说明书」缺专文

参考方法论有类代码规格说明书。LUMEN 分散在 `05 §4.2` 编码基线、`design-system`、`project-rules §5`，内容覆盖其实比参考方法论更全。**不建议新增文档**，作为实现阶段产出已在 05 承接的映射说明即可。
