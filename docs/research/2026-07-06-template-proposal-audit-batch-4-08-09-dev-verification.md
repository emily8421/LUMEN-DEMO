## 2. 总体结论

`docs/08-dev-plan.md` 已具备 Phase1 Sprint 拆分基础：每个 Sprint 都有目标、输入文档、修改范围、验收标准和禁止事项，符合早期模板的最小任务单要求。`tasks/*` 中也已有若干降级任务单，说明实际执行中确实需要将复杂 Sprint 拆成独立任务。

但从模板复用角度看，08 仍需要进一步细化，避免派生项目出现以下问题：

1. 有 Sprint 详情，但缺少 Phase 目标、Sprint 总览、依赖关系、任务拆分决策和当前进度记录。
2. Sprint 输入文档常只列文件名，未精确到 REQ、设计章节、API-ID、表名、TC-ID。
3. Sprint 修改范围以模块名为主，缺少“预计文件 / 模块数量、是否触发拆 task、是否需要 worktree”的判断。
4. 验收标准只写自然语言，缺少与 `docs/09-verification.md` TC-ID、测试等级、验证命令、人工步骤和资源验证的连接。
5. Sprint 完成后，`docs/08`、`tasks/*`、`docs/09`、续接文件、Git 提交之间缺少统一的完成包记录口径。
6. 降级任务、Mock / Demo 任务和真实能力任务之间缺少状态分类，容易将降级完成误读为真实能力完成。

`docs/09-verification.md` 的细化问题已在 P-05 提案中覆盖，本 Batch 不重复起草 09 提案；P-04 应聚焦 08 与 `tasks/*` 的计划、进度和完成包规范，并明确如何引用 09。

## 3. `docs/08-dev-plan.md` 观察

### 3.1 已满足项

- 文档元信息声明当前 Phase、交付物形态、输入基线、状态和最后更新日期。
- Sprint-1 到 Sprint-6 均包含目标、输入文档、修改范围、验收标准、禁止事项。
- Sprint 边界大体遵守小步快跑，未把整个系统塞进单个 Sprint。
- Sprint-6 明确是桌面端横切验收，不新增功能。
- 待人工确认项说明实际执行状态以任务 / PR / 续接记录为准。

### 3.2 模板缺口

- 缺少 `当前 Phase 目标` 独立章节，无法一眼看到 Phase 功能范围、交付物形态、退出标准和禁止越界。
- 缺少 `Phase / Sprint / Task 定义`，新会话或新工具容易混淆阶段、迭代和单任务。
- 缺少 `Sprint 总览` 表，无法快速查看所有 Sprint 的 REQ、修改范围、验证包和状态。
- 缺少 `依赖关系与里程碑` 表，无法表达 Sprint 之间的前置依赖、阻塞风险和并行策略。
- 缺少 `任务拆分规则` 在文档内的项目化落点；实际 `tasks/*` 已启用，但 `08` 未记录哪些 Sprint 被拆分、拆分原因、任务单路径和状态。
- 缺少 `当前进度记录` 或“执行状态表”；导致完成事实依赖 Git / PR / 续接文件，正式文档自身不易审计。
- Sprint 详情缺少 `验证包` 和 `Sprint 完成包` 字段，无法稳定连接 09、测试命令、人工验收、残留风险和后续任务。

### 3.3 建议写入 P-04

- 增强 08 标准：Phase 目标、术语定义、Sprint 总览、Sprint 详情模板、依赖关系、任务拆分规则、当前进度记录。
- 将 `验证包` 与 `Sprint 完成包` 设为 Sprint 详情模板字段。
- 增加 `Sprint-ID`、`Task-ID`、`TC-ID`、状态枚举和完成包字段。
- 允许续接文件作为临时状态，但要求正式 Sprint / Phase 验收结果回填 09 或 08 进度记录。
- 对 Mock / 降级任务增加状态和“不等价真实能力完成”的说明字段。

## 4. `tasks/*` 观察

### 4.1 已满足项

- `tasks/README.md` 说明 Phase1 默认不强制启用 tasks，复杂 Sprint 再拆任务。
- 已存在 `task-003` 到 `task-007`，覆盖导入、搜索、RAG、前端搜索问答、术语管理等复杂或降级任务。
- 任务单包含目标、输入文档、修改范围、验收标准和禁止事项。

### 4.2 模板缺口

- 任务单模板缺少 Task-ID、所属 Sprint、关联 REQ、关联 TC、任务状态、验证命令、完成记录和残留风险。
- 降级任务没有统一字段说明“为什么降级、降级能力是否等价真实能力、何时补齐真实能力”。
- 多 AI / 多 worktree 并行时，任务单缺少分支 / worktree / 负责人 / 当前进度记录。
- 任务完成后缺少统一字段记录 Git commit / PR / 验证日志 / 09 验收记录路径。

### 4.3 建议写入 P-04

- 更新任务单推荐结构，增加 Task 元信息表。
- 增加 `降级 / Mock 边界` 条目。
- 增加 `完成记录` 条目。
- 在 `08` 中维护 Sprint → Task 路由表。
