## 1. 执行摘要

当前 00-03 已经能支撑 Phase1 Demo：空间隔离、权限、文档 CRUD、版本、导入、搜索、RAG 问答、术语、桌面端体验均有清晰需求与验收入口。结合 `08/09`，Phase1 核心闭环已经达到“可演示 + 部分真实化”的状态。

但用户当前目标不是继续做完整产品 MVP，而是尽快让 LUMEN 进入个人日常使用。因此，下一阶段不建议直接进入 Phase2 Team MVP；应先完成 P1.5 个人可用收口，优先解决资料批量入库、导出备份、基础稳定性与低风险知识组织。

## 3. 路线图重评估建议

| 建议阶段 | 定位 | 功能范围 | 达到效果 | 明确不做 |
|---|---|---|---|---|
| Phase1 Demo | 已完成的核心演示闭环 | REQ-001..011、REQ-036 | 能演示“导入 → 搜索 → 问答带来源 → 编辑版本 → 术语对齐” | 不追求批量资料管理与日常效率 |
| Phase1.5A 个人可用 Alpha | 下一步最优先 | REQ-037、REQ-038 + 登录 / 索引 / 权限稳定性收口 | 个人可以把一批资料放进去，搜得到、问得到、能编辑、能备份出来 | 不让 PDF、Word/PDF 真实解析、标签、AI 润色阻塞 |
| Phase1.5B 个人增强 Beta | Alpha 后增强 | REQ-027、REQ-009 真实 Word/PDF 文本提取、REQ-007 中文分词增强 | 可导出 PDF、更多格式可入库、中文搜索更顺手 | 不做 OCR、图谱、多人协作 |
| Phase2A 个人知识组织 | 资料变多后的轻组织 | REQ-026、REQ-012，REQ-025 可选 | 文档能互联、可按标签组织、资料不乱 | 不做完整时间轴 / 关系图，不做团队协作 |
| Phase2B 团队 MVP | 团队真实使用 | Phase2A 生产化 + REQ-014 / REQ-025 等 | 小团队能用知识组织与写作辅助 | 不做移动端、多人实时协作、跨空间推送 |
| 后续产品化 | 长期产品愿景 | OCR、飞书、Obsidian、分析图谱、因果 / 矛盾 / 证据地图 | 从知识库走向情报 / 分析平台 | 不作为近期编码目标 |

## 4. 推荐立即执行顺序

1. 先修订 `00-03`，把路线图从“产品 MVP 优先”改为“个人可用优先”。
2. 编码 Sprint-16：批量 / 文件夹导入。
3. 编码 Sprint-17：单文档 `.md` 下载 + 空间 ZIP 导出。
4. 补登录持久化、seed 自索引、外部只读写操作拦截等 P1.5 稳定性任务。
5. 再做 Sprint-18 PDF 导出；若 RG-006 不通过，不阻塞个人可用 Alpha。
6. 资料量上来后再做 REQ-026 内链 / 反链与 REQ-012 标签，而不是先做 AI 润色。

## 5. 本次应修改的文档点

- `00`：新增 P1.5 个人资料批量入库与导出备份场景，补下游影响。
- `01`：同步 U-33 到 P1.5，新增 U-43 导出 / 备份需求，补 P1.5 操作流与验收口径。
- `02`：覆盖范围更新至 REQ-001..038，REQ-038 绑定 U-43，补 P1.5 异常与验证入口。
- `03`：拆分 Phase1.5A / Phase1.5B，并把 Phase2 拆为 Phase2A 个人知识组织与 Phase2B 团队 MVP。

## 6. 风险提示

- PDF 导出依赖重，应受 RG-006 控制，不应成为个人可用 Alpha 的退出门槛。
- 真实 Word/PDF 文本提取和 OCR 是不同风险级别：前者可进入 P1.5B，OCR 应继续后置。
- 标签 / 内链是个人知识组织高 ROI 能力，可早于 AI 润色。
- 多人协作、移动端、跨空间推送不适合近期做，会显著拖慢个人可用目标。

## 7. 结论

建议立即把路线图改成“先个人可用，再团队 MVP”。最短路径是：批量导入 → 导出备份 → 稳定性收口 → 可选 PDF → 轻量知识组织。这样能最快让 LUMEN 从 Demo 变成个人日常可用工具。
