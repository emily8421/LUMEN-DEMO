## 2. 总体结论

`docs/06-db-design.md` 与 `docs/07-api-spec.md` 已具备 Phase1 详细契约基础：06 有表清单、P1 表字段、索引、关系和 REQ 追溯；07 有统一响应约定、接口清单、部分请求 / 响应示例和 REQ → 接口追溯。

从模板复用角度看，06-07 仍需要更强的“契约化”规范，避免派生项目出现以下问题：

1. DB 文档有表结构，但缺少数据需求概览、概念模型、生命周期、敏感性和迁移 / 初始化策略。
2. DB 字段缺少必填、默认值、约束、来源 REQ / NFR、PII / 敏感性、删除 / 留存等字段级约束。
3. DB 索引、唯一约束、外键、级联、查询模式和性能影响未形成统一表格。
4. API 文档有接口列表，但缺少稳定 API-ID、逐接口请求 / 响应契约、参数校验、错误示例、权限要求和兼容策略。
5. 文件上传、异步任务、导入 / OCR、RAG / LLM 等接口缺少状态机、降级 / Mock、外部服务失败和幂等口径。
6. DB 与 API 之间缺少模型字段、权限、错误码、测试用例的双向追溯，导致实现期容易出现文档与代码事实漂移。

结论：需要独立模板提案 P-03，建议文件名为 `_proposals/TEMPLATE-UPGRADE-06-07-db-api-contract-standard.md`。

## 3. `docs/06-db-design.md` 观察

### 3.1 已满足项

- 项目保留 `06` 的决策来源明确，符合 `ai/project-rules.md` 持久化存储裁剪规则。
- 有完整表清单，覆盖 P1、P2 和愿景阶段。
- P1 表结构较完整，覆盖用户、空间、成员、文档、版本、chunks、imports、terms。
- 有索引设计、表间关系和 REQ → 表追溯矩阵。
- P2 / 愿景表保持骨架，未提前细化远期字段。

### 3.2 模板缺口

- 规范应要求“数据需求概览”，明确哪些 REQ / NFR 需要持久化、数据对象用途、生命周期和敏感性。
- 规范应要求“概念模型”或 ER 图，用实体关系先解释数据模型，再进入物理表字段。
- 表结构模板应要求字段级 `必填 / 默认值 / 约束 / 来源 / 敏感性 / 留存`，而不只是字段、类型和说明。
- 索引与约束章节应拆分主键、唯一、外键、级联、查询索引、向量 / 全文索引和性能影响。
- 迁移与初始化章节应要求迁移工具、路径、命名、seed 数据、回滚策略、环境差异和数据修复口径。
- 数据安全与留存应要求访问控制、脱敏、加密、日志、删除策略、真实数据标注和外部 AI 发送边界。
- 对 Demo / Mock / 内存仓储与真实数据库之间的差异，应有“实现状态 / 迁移状态 / 不等价生产能力”的记录位。

### 3.3 建议写入 P-03

- 增加 `Data Object` 数据需求概览表。
- 增加 `Entity` 概念模型表和 `mermaid erDiagram` 建议。
- 增加字段级契约表，包含必填、默认值、约束、来源、敏感性、留存。
- 增加迁移与初始化模板。
- 增加数据安全与留存模板。
- 增加实现状态 / Demo 仓储 / Mock 数据与真实 DB 的差异说明。

## 4. `docs/07-api-spec.md` 观察

### 4.1 已满足项

- 保留 `07` 的决策来源明确，符合项目对外 REST API 裁剪规则。
- 有统一约定，包含 REST / JSON、Bearer Token、空间 + 文档权限、统一响应和错误码。
- 有完整接口清单，覆盖 P1、P2 和愿景阶段。
- 有部分 P1 请求 / 响应示例和接口交互时序图。
- 有 REQ → 接口追溯矩阵。

### 4.2 模板缺口

- 接口清单应要求稳定 API-ID，后续请求 / 响应 / 权限 / 错误 / 测试均引用同一 ID。
- 当前阶段接口应逐个写请求契约，包括路径参数、查询参数、请求体、multipart 字段、类型、必填、校验和示例。
- 当前阶段接口应逐个写响应契约，包括成功响应、失败响应、分页、异步状态、字段含义、空结果和来源引用等。
- 错误码章节应独立矩阵化，包含触发条件、HTTP 状态、业务码、用户可见信息、前端处理建议和日志 / 审计要求。
- 权限、安全与限流章节应逐接口说明鉴权要求、空间 / 租户 / 资源权限、敏感字段、审计日志、限流和越权失败策略。
- 兼容性与版本演进应说明破坏性变更、字段废弃、客户端影响、版本前缀或语义版本策略。
- 对 CLI、SDK、Event、Internal Contract 等非 REST 形态，模板应保留同等契约字段，而不是只面向 REST。
- API 契约应映射到前端调用、集成测试和 09 TC，避免只停在接口清单。

### 4.3 建议写入 P-03

- 增加 `API-ID` 贯穿 07 全文。
- 增加 endpoint 级请求 / 响应 / 错误 / 权限 / 兼容模板。
- 增加异步任务 / 文件上传 / 外部服务接口状态机模板。
- 增加 API → DB / Service / Test / TC 追溯表。
- 增加接口变更与版本兼容策略模板。

## 5. DB / API 交叉契约缺口

| 缺口 ID | 缺口 | 影响 | 建议提案内容 |
|---|---|---|---|
| B3-GAP-001 | DB 表 / 字段与 API 输出字段缺少统一映射 | 容易出现 API 返回字段与模型 / 表结构漂移 | 增加 `API 字段 → 数据来源 / 表字段 / 计算逻辑` 表 |
| B3-GAP-002 | 权限规则在 DB、API、Service、前端之间追溯不足 | 空间 / 租户 / 私有数据容易出现漏过滤 | 增加逐接口权限矩阵和 DB 查询边界引用 |
| B3-GAP-003 | 文件导入 / 异步任务状态契约不足 | 前端、API、DB 对 processing / done / failed 理解不一致 | 增加任务状态机和失败恢复字段 |
| B3-GAP-004 | 错误码与 DB 约束 / API 校验未映射 | 唯一约束、权限拒绝、资源不存在等实现期处理不一致 | 增加错误码 → 触发条件 → 约束 / 接口映射 |
| B3-GAP-005 | Mock / 降级与真实 DB / API 能力边界不足 | Demo 能力可能被误写成生产能力 | 增加实现状态、Mock / 降级、不等价真实通过说明 |
| B3-GAP-006 | API 契约未映射到 09 TC / 集成测试 | 接口变更后缺少验收回归锚点 | 增加 API-ID → TC-ID / 测试文件追溯 |

## 8. 提案拆分判断

本 Batch 建议只起草一个提案：

```text
_proposals/TEMPLATE-UPGRADE-06-07-db-api-contract-standard.md
```

原因：

- 06 与 07 都属于详细契约层，DB 字段、服务模型、API 请求 / 响应、错误码和权限边界高度耦合。
- 拆成 DB 提案与 API 提案会重复讨论权限、状态、Mock / 降级和测试追溯。
- 子系统内部流程和页面交互留给 P-06，不混入 P-03。
