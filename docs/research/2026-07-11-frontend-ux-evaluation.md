# 前端 UX 评估 + 目标布局对齐稿

> 定位：前端交互体验评估与目标布局提案（低保真对齐稿）。属 `docs/research/` 调研留痕。
> 依据：实测操作 + 源码 `frontend/src/App.tsx`（735 行单文件）+ `frontend/src/styles.css`。
> 不替代 `docs/design/frontend-interaction.md`；P1 确认后再回填该设计与 `ai/project-rules.md §2.7`。

## 0. 元信息

| 项 | 内容 |
|---|---|
| 日期 | 2026-07-11 |
| 评估对象 | Phase1 Demo 前端（React 单文件原型，Sprint-6 代码原型） |
| 结论 | 功能可用、视觉干净，但**结构与信息呈现**差：无导航/聚焦、Markdown 不渲染、结果不可点、不响应式 |
| 用户反馈 | "功能基本满足，但交互体验不太好，页面布局也不好" |

## 1. 根因

当前前端是 Sprint-6 为"桌面端验收 smoke"搭的**代码原型**（`project-rules §2.7` 明定"代码原型 + mock"）：
- 单文件 `App.tsx`（735 行）、**零组件库、零路由、零 Markdown 渲染**（仅 react/react-dom）。
- 三栏网格把**所有功能永远同时显示**，没有任务聚焦。
- `styles.css` 视觉本身不差（浅色卡片 + 蓝色强调 + 圆角阴影），问题主要在**结构与信息呈现**，不在配色。

## 2. 问题清单（对着代码）

### 布局
| # | 问题 | 代码位置 |
|---|---|---|
| L1 | 右栏 300px 塞 4 大块（版本 / 搜索 / RAG / 术语）竖排，又窄又长，无焦点 | `App.tsx` insight-panel；`styles.css` grid-template-columns `300px minmax(520px,1fr) 300px` |

## 3. 优化分级

| 级别 | 项 | 收益 | 成本 / 风险 |
|---|---|---|---|
| **P0 快赢** | I1/I2 Markdown 渲染（`react-markdown`）；I3 结果可点击跳转；X1 删除/恢复二次确认；L4 顶部改产品名 | 高（质感立升） | 低，仅 +1 轻依赖（react-markdown），不碰原型策略 |
| **P1 结构** | L3 引入导航/Tab/路由，右栏 4 块拆成「文档/搜索/问答/术语」独立视图；`App.tsx` 拆组件；L2 去掉 min-width + 响应式断点 | 高（聚焦、可扩展） | 中，改动大；可能引 react-router |
| **P2 打磨** | X2 toast+skeleton；X4 快捷键；X5 列表富信息/badge/命中高亮；暗色模式；空态插画 | 中 | 中 |

> **策略约束**：`project-rules §2.7` 现定"代码原型 + mock"。P0 仅加 `react-markdown`（已授权）。P1 若引 **react-router / 组件库（如 Ant Design）** 属新依赖（§2 须确认）+ 改原型策略（§2.7），需人工拍板。

## 4. 目标布局对齐稿（低保真，供确认后再做 P1）

> 原则：**左导航 + 主区按视图切换**（参考 Notion / Obsidian 这类知识库工具），让"文档/搜索/问答/术语"各占主区，不再同屏挤；文档列表在导航下常驻。

### 4.1 整体框架

```
┌──────────────────────────────────────────────────────────────┐
│ 💡 LUMEN · 团队知识库        [ nova-internal ▾ ]     alice ▾  │  ← 顶栏：产品名 + 空间切换 + 用户
├────────────┬─────────────────────────────────────────────────┤
│ 📄 文档     │                                                 │
│ 🔍 搜索     │              主内容区（按导航切换）              │
│ 💬 问答     │                                                 │
│ 📚 术语     │                                                 │
│ ─────────  │                                                 │
│ 文档列表    │                                                 │
│ • 场景联动  │                                                 │
│ • Nova 笔记 │                                                 │
│ …           │                                                 │
│ + 新建      │                                                 │
└────────────┴─────────────────────────────────────────────────┘
│ 状态栏 / toast 提示                                           │
```
- 左导航：上半图标入口（文档/搜索/问答/术语），下半当前空间文档列表 + 新建。
- 顶栏：产品名（去 Sprint 占位）、空间切换（更醒目）、用户菜单。
- 主区：随导航切换，每次只聚焦一个任务。

## 5. 响应式策略（P1）

| 宽度 | 布局 |
|---|---|
| ≥ 1200px | 左导航（240px）+ 主区（自适应），如上 |
| 768–1199px | 左导航收成图标栏（64px）；文档列表抽屉化（点📄展开） |
| < 768px | Phase1 不承诺移动端（`project-rules §1` 禁止），但保证**桌面窄窗口不横滚**（去掉 `min-width:1180px`） |

> Phase1 仅承诺桌面端；响应式目标是"桌面任意宽度不破版"，非移动适配。

## 6. 建议执行顺序

1. **P0（先做，已授权）**：见 §3 P0 行——独立小 PR，立竿见影，不碰策略。
2. **确认本对齐稿**：你在 §4 的目标布局上拍板（导航形式、视图划分、术语左右分栏等）。
3. **P1（确认后）**：按确认稿做结构重构（路由/Tab + 拆组件 + 响应式）；若引 react-router/组件库，先更新 `project-rules §2.7` 并确认新依赖。
4. **P2（可选）**：toast/skeleton/快捷键/富列表/暗色。
