## 2. 图纸体系设计（核心：图纸驱动编码）

**图纸族 + 驱动链**（每阶段图纸 → 下一产物 → 编码）：

| 图纸族 | 图 ID | 阶段 | 驱动什么 |
|---|---|---|---|
| 用例图 | `DIAG-UC-*` | 需求分析 | 驱动 AC/TC 验收（09） |
| 领域模型（分析类图） | `DIAG-DOM-*` | 需求分析 | 驱动 06 物理表 |
| 架构 / 组件图 | `DIAG-ARCH-*` | 概要设计 | 驱动 05 技术 + 08 骨架 |
| 概设交互图 | `DIAG-ARCH-SEQ-*` | 概要设计 | 驱动 07 接口时序 |
| **概设类图** | `DIAG-CLS-PRELIM-*` | 概要设计 | 驱动详细类图 |
| **详细类图** | `DIAG-CLS-*` | 详细设计 | **驱动类代码**（方法签名 / 参数 / 算法） |
| 活动 / 状态图 | `DIAG-*-FLOW/STATE` | 详细设计 | **驱动流程 / 状态机代码** |
| ERD | `DIAG-DB-ER-*` | 详细设计 | 驱动 06 / 迁移 |

**图纸 → 编码转换链**：
```
用例图 → AC/TC（验收）
领域模型 → 06 表
概设类图 → 详细类图
交互图 → 07 接口
详细类图 → 类代码（service / repository / entity 的方法与参数）
活动/状态图 → 流程 / 状态机代码（框架伪代码 + 算法伪代码）
```

**LUMEN 落地取舍**：
- 后端（FastAPI Python）用**详细类图 `DIAG-CLS-*`**（service / repository / entity 关键类）驱动编码。
- 前端（React）用 `frontend-interaction.md`（组件职责 / 状态 / 接口依赖）驱动——不强行给前端画 OO 类图。
- 类图与「数据 / 接口契约」互补：契约驱动"表 / 接口"，类图驱动"服务对象与方法"。
