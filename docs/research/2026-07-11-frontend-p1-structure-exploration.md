## 4. 候选需求与验收

| NEED-ID | 痛点 | 用户目标 | 候选需求 | AC-DRAFT-ID | 非目标 |
|---|---|---|---|---|---|
| NEED-01 | 所有功能同屏常驻导致无任务聚焦 | 用户能选择当前任务视图，只看与任务相关的信息 | 前端应提供一级导航 / Tab，在“文档 / 搜索 / 问答 / 术语”之间切换主内容区 | AC-DRAFT-01：点击导航项后，仅主区切换到对应视图；当前空间上下文保持不变 | 不做多页面权限边界；权限仍以后端 API 为准 |
| NEED-02 | 右栏面板堆叠导致版本 / 搜索 / 问答 / 术语互相挤压 | 辅助信息只在相关任务中出现 | 将右栏 4 大块拆回各自视图：版本属于文档视图，搜索属于搜索视图，RAG 属于问答视图，术语采用列表 + 编辑布局 | AC-DRAFT-02：进入搜索视图时不显示版本和术语表单；进入术语视图时不显示文档编辑器 | 不新增 P2 标签 / 反链 / AI 润色能力 |
| NEED-03 | 搜索 / 问答任务阅读空间不足 | 用户能在大主区阅读答案、来源与摘要 | 搜索和问答视图应使用主区宽度，保留 P0 的 Markdown 渲染与来源打开能力 | AC-DRAFT-03：问答答案和来源在主区完整展示，无 300px 右栏压缩 | 不做命中高亮、toast、skeleton 等 P2 打磨 |
| NEED-04 | 固定 `min-width` 导致桌面窄窗口横滚 | 演示者在桌面不同宽度下不破版 | 去掉全局 `min-width:1180px`，增加桌面响应式断点：>=1200 常规侧栏，768–1199 压缩导航 / 单列主区 | AC-DRAFT-04：浏览器宽度 900px 下不出现全局横向滚动，可完成登录、文档、搜索、问答主流程 | 不承诺手机端 / 移动端适配 |
| NEED-05 | `App.tsx` 单文件持续膨胀，结构优化风险高 | 开发者能小步维护各页面 | 将 `App.tsx` 拆成轻量组件与 hooks / helpers，按页面组织 UI，但保持现有 API 封装不变 | AC-DRAFT-05：拆分后 `npm.cmd run build` 通过；核心功能 smoke 通过；不新增后端接口 | 不引入全局状态管理；不重写 API 层 |

## 5. 方案比较

| 方案 | 内容 | 优点 | 风险 / 成本 | 结论 |
|---|---|---|---|---|
| A. 纯 React state Tab + 纯 CSS（推荐） | 在单页内用 `activeView` 切换“文档 / 搜索 / 问答 / 术语”；拆组件；加响应式 CSS | 无新依赖，符合当前代码原型策略；能解决聚焦和右栏拥挤；PR 可控 | URL 不可深链；刷新后回默认视图 | **推荐作为 P1 首版** |
| B. 引入 `react-router` | 使用路由表达 `/documents`、`/search`、`/query`、`/terms` | 深链、浏览器前进后退更自然；后续扩展更清晰 | 新依赖需确认；需更新 `project-rules §2.7` / 技术文档；改动更大 | 可作为 P1.5 或用户确认后做 |
| C. 引入组件库（Ant Design 等） | 用现成 Layout / Menu / Tabs / Form / Drawer | 视觉统一，表单和布局效率高 | 新依赖体积和风格迁移成本高；可能重写大量 CSS | 暂缓，等 P1A 后再评估 |
| D. 保留三栏，仅局部折叠右栏 | 不做导航，只把右栏卡片折叠 / accordion | 改动最小 | 不能根治任务聚焦；页面仍复杂 | 不推荐 |

## 6. 推荐 P1 范围

### 6.1 P1A：结构聚焦（推荐先做）

| 项 | 建议 |
|---|---|
| 导航 | 左侧固定导航，保留空间切换和文档列表入口 |
| 视图 | `documents` / `search` / `query` / `terms` 四个主视图 |
| 状态 | 使用本地 `activeView`，不引入路由 |
| 组件拆分 | 拆 `Sidebar`、`DocumentView`、`SearchView`、`QueryView`、`TermsView`、`StatusBar` |
| 响应式 | 去掉 `body min-width`；桌面 768–1199px 下侧栏压缩或上置；不承诺手机端 |
| 保留能力 | P0 Markdown 渲染、结果点击、二次确认全部保留 |
| 验证 | `npm.cmd run build` + 浏览器 smoke：登录、切视图、文档、搜索、问答、术语、窄窗口 |

### 6.2 暂不进入 P1A

| 项 | 原因 | 后续 |
|---|---|---|
| `react-router` | 新依赖 + 范围扩大；当前没有 URL 深链硬需求 | P1A 后评估是否需要 P1.5 |
| 组件库 | CSS 现状不差，核心问题是结构；组件库会放大 PR | P2 观感打磨时再评估 |
| 移动端 | `project-rules` 禁止 Phase1 移动端；当前只做桌面不破版 | 后续 Phase 独立确认 |
| P2 打磨 | toast / skeleton / 快捷键 / 命中高亮属于体验增强 | P1A 结构稳定后再做 |
