## 2. 信息架构方向

### 2.1 分层模型

```text
Layer 0  空间层（Space）
  └─ Layer 1  空间总览：项目 / 主题聚合瓦片
      └─ Layer 2  项目 / 主题内部：子目录继续聚合，面包屑常驻
          └─ Layer 3  叶子文件夹：默认传统列表 / 表格
              └─ Layer 4  单篇文档：统一阅读器 / 编辑器 / 版本体验
```

### 2.2 模式切换

| 模式 | 作用 | 默认建议 | 约束 |
|---|---|---|---|
| 经典模式 | 目录树、列表、表格、搜索 | 大规模文档和新用户默认可靠路径 | 必须始终可达，不被探索模式覆盖 |
| 探索模式 | 聚合瓦片、局部关系图、可视化筛选 | 用于建立全貌、发现关系和定位待核实问题 | 只在有边界集合内启用，节点过多时自动降级 |

### 2.3 视图自动降级候选规则

| 节点 / 文档数量 | 默认视图 | 探索视图口径 | 状态 |
|---:|---|---|---|
| ≤ 25～30 | 探索视图可作为默认候选 | 可完整展示局部瓦片 / 关系图 | 经验候选，待真实数据标定 |
| 30～80 | 传统列表为默认 | 用户主动点击后可用；自动聚类并合并次要节点 | 经验候选，待真实数据标定 |
| 80+ | 传统列表 / 表格强制默认 | 先按标签 / 时间窗口 / 关键词缩小范围，再生成局部图 | 经验候选，待真实数据标定 |

### 3.1.1 多主题方向（2026-08-16 UI-G-003 已确认）

> 依据：`docs/research/2026-08-16-frontend-ui-reference-analysis-theme-pilot.md`（主题专项 RA）+ `docs/research/2026-08-16-ui-visual-exploration.md`（视觉探索 + WCAG 对比度校验）+ `docs/research/2026-08-16-ui-theme-pilot-prototype.html`（静态原型）。用户 2026-08-16 拍板（UI-G-003 通过）：

| 主题 | 定位 | 状态 |
|---|---|---|
| A 浅色精修（`light`） | 默认主题；沿明亮蓝白基底，2 处对比度修订（muted `#5f6f88` / red `#c81e1e`） | **已确认视觉方向**，待实现 |
| B 深色（`dark`） | 近黑画布 + 面板阶梯 + 提亮主色 `#5b8cff`；语义色提亮 + 13-14% 软底 | **已确认视觉方向**，待实现 |
| C 暖米纸（`paper`） | 暖纸画布 + 暖墨 + 珊瑚主色（按钮 `#b5542f` / 文字 `#a84a28` 双档）；衔接本表既有「米白」候选 | **已确认视觉方向**，待实现 |
| 原稿冻结（`legacy`） | 试点前现状配色原样冻结为对照主题；含 2 处对比度历史值（4.40/4.41），**留证不改** | **已确认保留为对照**，不推荐日常使用 |
| 代码块 | 四套统一固定深色 `#1c1c1e`，不随主题变（C-RA-002 拍板） | **已确认** |

配套机制约束（随实现落地）：

- 主题层只改色板（CSS variables `[data-theme]`），层级 / 密度 / 布局信号四套完全一致（RA 约束，承接 PAT-VIS-001/003/006）。
- 全部主题过 WCAG 2.2 对比度门槛（PAT-VIS-005，A 级）：正文 ≥4.5:1、大字 / 组件 ≥3:1。
- `legacy` 中的历史对比度缺陷在文档标注留证，不回改——对照价值优先。

**新增主题三步法**（2026-08-16 主题试点实现沉淀；契约注释同步见 `frontend/src/theme.ts` 头部）：

1. `frontend/src/styles/tokens.css` 追加一个 `[data-theme='<name>']` 块，整块变量**填全**（推荐复制 `light` 块改值；漏 token 会回落 `:root` 默认值，深色系主题会出穿帮白块）。
2. `frontend/src/theme.ts` 的 `THEMES` 数组加一行 `{ value: '<name>', label: '<中文名>' }`。
3. `frontend/index.html` 防闪烁预置脚本的白名单加同名值（漏改症状：平时正常、刷新瞬间闪回浅色）。

组件 CSS 一行不用动——只要颜色全走 `var(--xxx)`，新主题就是纯 tokens.css 的事（CSS 纪律见 `ai/project-rules.md` §5.1，CI 守门 `npm run check:css`）。动手前先按 WCAG 对比度门槛校验色值（参照 `docs/research/2026-08-16-ui-visual-exploration.md` §1 的 token 表与校验口径）；主色可能需要「按钮底 / 文字」双档（C 套先例）。

| 原备选主题行「更温和的米白、浅青主题」 | 已升级为正式 C 套主题方向（上表）；「浅青」暂不展开 | 已收敛 |

### 3.2 密度方向

- 延续 P1B 高密度工作台原则：列表行、工具栏、Inspector、分隔线优先。
- 空间总览瓦片用于表达项目 / 主题状态，不用于展示全部文档细节。
- 叶子文件夹内文档数量较多时，默认列表 / 表格，支持筛选、排序、搜索、分页或虚拟滚动。
- 单篇文档继续保持可读 / 可编辑，不因入口不同而变化。

### 3.3 文案方向

- 未验证关系使用“候选关系 / 待确认关系”，不写成“已发现真相”。
- 高风险 AI 能力前期使用“待核实问题”，谨慎使用“矛盾 / 冲突”。
- 问答无来源时沿用 P1 红线：“未在当前空间知识库找到”。
- 权限拒绝沿用 P1 口径：“无权限或资源不存在”，不泄露其他空间信息。
