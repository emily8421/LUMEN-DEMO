# 软件系统面向对象开发方法的过程要点及关系

> 本文根据流程图整理，梳理面向对象软件开发从需求获取到编码实现的五个阶段，
> 及各阶段产出的**文档**、**图（模型）**与相互间的**转换/抽取关系**。
> P1 归位说明（2026-07-21）：本文已从 `docs/inputs/` 归位到 `docs/references/`，作为外部方法论参考；它不是 LUMEN 项目流程权威。正式引用前需人工校对原图 / 原始资料。

## 1. 总体阶段划分

软件开发过程自左向右分为五个阶段：

```
需求获取与说明阶段 → 需求分析阶段 → 概要设计阶段 → 详细设计阶段 → 实现（编码调试）阶段
```

各阶段核心产出物对应关系概览：

| 阶段 | 核心图 / 模型 | 核心文档 |
|---|---|---|
| 需求获取与说明阶段 | 实体-联系图（ERD）、"事物-事件"表 | 项目策划说明书、用户需求说明书 |
| 需求分析阶段 | 分析阶段的类图、用例图 | 软件需求规格说明书 |
| 概要设计阶段 | 概设阶段的类图、交互图（顺序图/协作图） | 概要设计规格说明书 |
| 详细设计阶段 | 详细阶段的类图、活动/状态图 | 详细设计规格说明书 |
| 实现（编码调试）阶段 | 类代码 | 类代码规格说明书 |

---

## 2. 各阶段详细内容

### 2.1 需求获取与说明阶段

**输入**：项目策划说明书
- 可行性分析报告
- 立项报告
- 项目开发计划

**核心产出图**：
- **实体-联系图（ERD）**：抽取实体及其联系
- **"事物-事件"表**：按"主谓宾"形式，从需求描述的文本中提取主语及相应的谓语动词（即"事件"），抽取事件及其关联对象，形成事物与事件的二维关系，简称"E-E 表"

**核心产出文档**：**用户需求说明书**
- 方式一：用户需求说明（调研式）
- 方式二：用户需求说明（叙事式）
  - 想定（愿景的构想模式）：
    1. 企业立案
    2. 基本设定
    3. 补充（附加）构想
  - 5W1H（愿景的叙述模式）：*When, Where, Who/Whom, Why, What, How, How much*
- 可选附件：《事物-事件》表
- 可选附件：E-R 图

---

### 2.2 需求分析阶段

**核心产出图**：
- **分析阶段的类图**：由 ERD、"事物-事件"表进一步抽取而来，识别"实体"作为类/对象，识别"联系"作为"事件"或"方法"，识别"属性"作为类的属性
- **用例图**：抽取用例及关联作为交互（用例之间的使用关系）

**核心产出文档**：**软件需求规格说明书**
- 需求规格说明
- 附件1：用例图
- 附件2：分析阶段的类图

要点：
- 明确划出"边界"用例，以及被边界外使用的内部用例
- 在分析阶段，只考虑"功能"用例，不要考虑创建对象所需要的"构造"用例

---

### 2.3 概要设计阶段

**核心产出图**：
- **概设阶段的类图**：组成与结构设计（类及彼此交互），补充属性与方法
- **交互图（顺序图/协作图）**：对象交互的方式（交互 = 用例之间的使用关系；交互图 = 角色与用例之间的使用关系）

**核心产出文档**：**概要设计规格说明书**
- 总体设计规格说明
- 接口设计规格说明
- 运行设计规格说明
- 系统数据结构设计
- 出错处理设计
- 附件1：概设阶段的类图
- 附件2：交互图（顺序图或协作图）

要点：在设计阶段，必须考虑增加系统实现对象所需的"构造"类——由它来完成对象所需的"构造"

---

### 2.4 详细设计阶段

**核心产出图**：
- **详细阶段的类图**：组成内部逻辑设计，完善类与属性
- **活动/状态图**：对象交互过程 → 框架（伪）代码；逻辑变换过程 → 算法（伪）代码

**核心产出文档**：**详细设计规格说明书**
- 详细设计规格说明
- 附件1：活动或状态图
- 附件2：详细阶段的类图

---

### 2.5 实现（编码调试）阶段

**核心产出**：
- **编码**：全局交互过程 → 框架（伪）代码
- **类代码**：逻辑变换过程 → 算法（伪）代码；逻辑变换 → 活动/状态图转移逻辑

**核心产出文档**：**类代码规格说明书**
- 遵循的编码规范
- 遵循的其它工业标准
- 变量名称规范
- 数据规范实例
- 语句结构规范说明
- 注释规范说明
- 附件1：类代码及注释

## 3. 阶段间的核心转换/抽取关系

| 编号 | 转换关系 | 说明 |
|---|---|---|
| ① | 项目策划说明书 → 用户需求说明书 | 抽取事物与事件 |
| ② | 用户需求说明书 → 实体-联系图（ERD） | 抽取实体及其联系 |
| ② | 用户需求说明书 → "事物-事件"表 | 抽取"事物"作为①"事物"/②"类"，抽取"联系"作为①"事件"/②"方法"，抽取"属性"作为①"事物"/②"类"共有名称的"属性" |
| ③ | ERD / "事物-事件"表 → 用例图 | 抽取用例及关联作为交互（交互 = 用例之间的使用关系） |
| ③ | ERD / "事物-事件"表 → 分析阶段的类图 | 抽取客体形成类 |
| ④ | 分析阶段的类图 → 概设阶段的类图 | 组成与结构设计（类及彼此交互） |
| ⑤ | 用例图 → 交互图 | 抽取用例及关联作为交互 |
| ⑥ | 交互图 → 概设阶段的类图 | 对象与交互 → 属性和方法（以对象的行为形成：交互、生成方法） |
| ⑦ | 概设阶段的类图 → 详细阶段的类图 | 逻辑变换 → 方法与属性（方法名、参数、参数类型、算法逻辑） |
| ⑧ | 交互图 → 活动/状态图 | 对象交互方式 → 活动/状态转移逻辑 |
| ⑨ | 详细阶段的类图 / 活动状态图 → 类代码 | 编写类代码 |
| ⑩ | 活动/状态图 → 类代码 | 全局交互过程 → 框架（伪）代码；逻辑变换过程 → 算法（伪）代码 |

> 说明：图中转换关系以带圈数字（①~⑩ 及更多细分编号）标注在各图/文档之间的连线上，
> 上表为按转换发生的阶段顺序归纳整理，部分细分编号（如②-(2)等）因图面文字过密、
> 存在无法完全辨识的情况，建议对照原图核实后再作为正式规范引用。

## 4. 图例说明（关联图符号）

| 符号 | 含义 |
|---|---|
| 事物 → 事件 → 事物 | 表示"事物"经由"事件"关联到另一"事物" |
| 事件：(事物, 事物) | 事件以其关联的两个事物表示 |
| 事物 ⇄ 事件 ⇄ 事物 | 事物与事件间的双向关联关系图 |

## 5. 备注

1. 软件开发过程中，初学者通常会忽略从需求获取或需求分析阶段到需求分析阶段的抽取过程。
2. 描述需求的两种句式：**"(事物) 事物1"**，或 **"(事物A, 事物1, 事件B)"**，如事物-事件表。
3. 图中符号 **"/"** 表示"或者"。
