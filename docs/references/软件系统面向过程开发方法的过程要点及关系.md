# 软件系统面向过程开发方法的过程要点及关系

> 本文根据流程图整理，梳理面向过程软件开发从需求获取到编码实现的五个阶段，
> 及各阶段产出的**文档**、**图（模型）**与相互间的**转换/抽取关系**。
> P1 归位说明（2026-07-21）：本文已从 `docs/inputs/` 归位到 `docs/references/`，作为外部方法论参考；它不是 LUMEN 项目流程权威。正式引用前需人工校对原图 / 原始资料。

## 1. 总体阶段划分

软件开发过程自左向右分为五个阶段：

```
需求获取与说明阶段 → 需求分析阶段 → 概要（系统结构）设计阶段 → 详细（软件模块）设计阶段 → 实现（编码调试）阶段
```

各阶段核心产出物对应关系概览：

| 阶段 | 核心图 / 模型 | 核心文档 |
|---|---|---|
| 需求获取与说明阶段 | 实体-联系图（ERD）、事物-事件表 | 项目策划说明书、软件需求用户说明书 |
| 需求分析阶段 | 数据流图（DFD）、数据词典 | 软件需求规格说明书 |
| 概要（系统结构）设计阶段 | 软件模块结构图（SMSD）、数据词典 | 概要设计规格说明书 |
| 详细（软件模块）设计阶段 | 软件主程序伪代码、软件模块的算法说明、软件模块的数据结构说明、程序复杂度说明 | 详细设计规格说明书 |
| 实现（编码调试）阶段 | 源代码 | 源代码规格说明书 |

---

## 2. 各阶段详细内容

### 2.1 需求获取与说明阶段

**输入**：项目策划说明书
- 可行性分析报告
- 立项报告
- 项目开发计划

**核心产出图**：
- **实体-联系图（ERD）**：抽取实体及其联系
- **事物-事件表**：按"主谓宾"形式，从需求描述的文本中抽取主语和宾语（即"事物"），抽取动词短语（谓语宾语，即"事件"），由此构成一个二维关系，简称"O-E"表

**核心产出文档**：**软件需求用户说明书**
- 需求用户说明
- 甚至附加：
  - 附件1：E-R 图
  - 附件2：事物-事件表

---

### 2.2 需求分析阶段

**核心产出图**：
- **数据流图（DFD）**：
  1. 抽取系统内实体作为数据流
  2. 抽取实体间联系作为加工
- **数据词典**（第一版，对应 DFD）：
  - 加工
  - 数据流（成分是数据项）
  - 存储（成分也是数据项）
  - 数据项

**核心产出文档**：**软件需求规格说明书**
- 需求规格说明
- 附件1：数据流图
- 附件2：数据词典

---

### 2.3 概要（系统结构）设计阶段

**核心产出图**：
- **软件模块结构图（SMSD）**：由数据流图转换而来（区分扇入/扇出、模块划分策略、耦合与内聚控制）
- **数据词典**（第二版，对应 SMSD）：
  - 加工
  - 数据流（成分是数据项）
  - 存储（成分也是数据项）
  - 数据项

**核心产出文档**：**概要设计规格说明书**
- 模块划分规格说明
- 系统结构规格说明
- 模块接口规格说明
- 全局数据规格说明
- 附件1：软件模块结构(SMS)图
- 附件2：数据词典

---

### 2.4 详细（软件模块）设计阶段

**核心产出图**：
- **软件主程序伪代码**：设计程序的逻辑主控流程
- **软件模块的算法说明**：伪代码、流程图、NS 图、Jackson / PAD / Warnier / IFO 图、判定表/判定树
- **软件模块的数据结构说明**：Jackson 方法、ADT（抽象数据类型）方法
- **程序复杂度说明**：代码行度量法、McCabe 方法、Halstead 方法

**核心产出文档**：**详细设计规格说明书**
- 程序伪代码规格说明
- 框架（主程序）和模块的数据结构规格说明
- 框架（主程序）和模块的算法规格说明
- *框架（主程序）和模块的算法复杂度规格说明*
- 附件1：框架和模块的抽象数据类型（ADT）表或图
- 附件2：框架和模块的算法伪代码或程序流程图
- 附件3：核心算法复杂度分析的表或图

---

### 2.5 实现（编码调试）阶段

**核心产出**：
- **源代码**：由伪代码框架编码而来

**核心产出文档**：**源代码规格说明书**
- *遵循的编码规范*
- *遵循的其它工业标准*
- *变量名的规格说明*
- 数据规格说明
- 语句结构规格说明
- 注释规格说明
- 附件1：源代码及注释

---

## 3. 阶段间的核心转换/抽取关系

| 编号 | 转换关系 | 说明 |
|---|---|---|
| ① | 项目策划说明书 → 软件需求用户说明书 | 抽取事物与事件 |
| ② | 软件需求用户说明书 → 实体-联系图（ERD） | 1. 抽取"实体"作为"事物"；<br>2. 抽取"实体间的作用关系"作为"事件" |
| ③ | 事物-事件表 → 数据流图（DFD） | 1. 抽取客体作为数据流（客体：受外来作用的事物）；<br>2. 抽取事件的动词及关联作为加工（加工＝事件牵引的作用动作，作用于客体）；<br>3. 抽取被牵涉的文件客体作为存储 |
| ④ | 事物-事件表 → 数据词典 | 1. 抽取客体作为数据流；<br>2. 抽取事件的动词作为加工 |
| ⑤ | 实体-联系图（ERD） → 数据流图（DFD） | 1. 抽取系统内实体作为数据流；<br>2. 抽取实体间联系作为加工 |
| ⑥ | 实体-联系图（ERD） → 数据词典 | 1. 抽取实体作为数据流；<br>2. 抽取实体所有属性作为数据项；<br>3. 抽取实体之间的联系作为加工 |
| ⑦ | 数据流图 → 软件模块结构图 | 区分扇入/扇出，转换为模块结构 |
| ⑧ | 数据流图（DFD） → 软件模块结构图（SMSD） | 1. 抽取输入区数据流，作为输入模块；<br>2. 抽取所有加工，作为实现模块；<br>3. 抽取输出区数据流，作为输出模块 |
| ⑨ | 软件模块结构图 → 软件主程序伪代码 / 算法说明 / 数据结构说明 | 1. 抽取加工逻辑，设计程序的运算与控制过程；<br>2.（⑨-1/⑨-2/3）抽取数据流，设计程序的宏观数据结构；<br>3. 抽取存储，设计数据文件的数据结构 |
| ⑩ | 软件模块结构图 → 程序复杂度说明 | 模块结构复杂度初步评估依据 |
| ⑪ | 软件主程序伪代码 → 源代码 | 1. 按"左深模块优先"将输入区编号；<br>2. 按"左模块优先"将主加工区编号；<br>3. 将输出区按"左浅模块优先"编号；<br>4. 按照模块编号依次写出其标识的文字 |
| ⑫ | 软件主程序伪代码/源代码 → 程序复杂度说明 | 1. 抽取程序控制流；<br>2. 预测程序长度；<br>3. 计算实际程序长度；<br>4. 定义程序词汇表；<br>5. 计算程序难度比；<br>6. 计算程序员工作量；<br>7. 统计源码复杂度 |
| ⑬ | 源代码 → 框架编码 / 模块算法编码 / 模块数据结构编码 | 1. 框架编码；<br>2. 模块算法编码；<br>3. 模块数据结构编码 |

> 说明：图中转换关系以带圈数字标注在各图/文档之间的连线上，上表为按转换发生的阶段顺序归纳整理，
> 部分细分编号（如 ⑨-1、⑨-2/3 等）因图面文字密集、字号较小，存在无法完全辨识的情况，
> 建议对照原图核实后再作为正式规范引用。

## 4. 图例说明（事物-事件关系图）

| 符号 | 含义 |
|---|---|
| 事件1 → (事物1) → 事件A | 事件1 经由 事物1 关联到 事件A |
| 事件A → (事物2) → 事件B | 事件A 经由 事物2 关联到 事件B |

图示结构：事物1 → 事件A → 事物2 → 事件B（事件关系图）

## 5. 备注

1. 软件开发过程中，初学者通常会忽略从需求形成阶段到需求分析阶段的抽象过程。
2. 描述需求的两种句式：**(事件A, 事物1)**，或 **(事件A, 事物1, 事件B)**，如事件关系图。
3. 图中符号 **"/"**、**"○"** 分别表示"或者"、"和步骤序列"。
