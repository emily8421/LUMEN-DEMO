## 第1章 文件结构
每个C++/C程序通常分为两个文件。一个文件用于保存程序的声明（declaration），称为头文件。另一个文件用于保存程序的实现（implementation），称为定义（definition）文件。
C++/C程序的头文件以“.h”为后缀，C程序的定义文件以“.c”为后缀，C++程序的定义文件通常以“.cpp”为后缀（也有一些系统以“.cc”或“.cxx”为后缀）。
【规则1-0-1】使用*.h作为c++ class的头文件名后缀；
【规则1-0-2】使用*.cpp作为c++ class的源文件名后缀；
【规则1-0-3】使用*.h作为c程序的头文件名后缀；
【规则1-0-4】使用*.c作为c程序的源文件名后缀。
### 1.1 版权和版本的声明
版权和版本的声明位于头文件和定义文件的开头（参见示例1-1），主要内容有：
版权信息；
文件名称，相关描述；
当前版本号，作者，修改日期；
版本信息；
编辑历史。
【规则 1-1-1】文件开头要有版权信息，文件名称，相关描述。

### 2.4 长行拆分
【规则2-4-1】代码行最大长度宜控制在80个字符以内。代码行不要过长，否则眼睛看不过来，也不便于打印。
【规则2-4-2】长表达式要在低优先级操作符处拆分成新行，操作符放在新行之首（以便突出操作符）。拆分出的新行要进行适当的缩进，使排版整齐，语句可读。
### 2.5 修饰符的位置
【规则2-5-1】应当将修饰符 * 和 ＆ 紧靠变量名。
例如：  char *strName;
    int  *x, y;   /* 此处y不会被误解为指针。 */
### 2.6 注释
C语言的注释符为“/*…*/”。C++语言中，程序块的注释常采用“/*…*/”，行注释一般采用“//…”。
但请注意！本规范对程序块的注释规定为“多行注释形式构成注释块”。形式如：

/* ***********************************************************************************
*
*
*  本规范对程序块的注释规定为“多行注释形式构成注释块”
*
*
****************************************************************************************
 */注释通常用于：
版本、版权声明；
函数接口说明；
重要的代码行或段落提示。
【建议2-6-1】如果代码本来就是清楚的，则不必加注释。
【规则2-6-2】边写代码边注释，修改代码同时修改相应的注释，以保证注释与代码的一致性。不再有用的注释要删除。
【规则2-6-3】注释应当准确、易懂，防止注释有二义性。
【规则2-6-4】尽量避免在注释中使用缩写，特别是不常用缩写。
【规则2-6-5】注释的位置应与被描述的代码相邻，可以放在代码的上方或右方，不可放在下方。
【规则2-6-6】当代码比较长，特别是有多重嵌套时，应当在一些段落的结束处加注释，便于阅读。
【规则2-6-7】在头文件中的函数声明之前，要给出恰当的注释，从而让使用者无需了解实现细节就能快速获得足够的信息来使用该函数；在函数实现之前，要给出与实现有关的足够而精炼的注释信息，注释格式如下。

/* ***********************************************************************************
*  Description: <功能描述>
*  Input:  <输入参数及其描述>
*  Output:   <输出参数及其描述>
*  Return:  <返回值及其描述>
*  Exception: <异常情况描述>
****************************************************************************************
 */类的版式
【建议2-7-1】public在protected之上，protected在private之上。
【建议2-7-2】成员函数在成员变量之上。
## 第3章 命名规则
### 3.1 类型命名
类型包括：class，struct，union，typedef，enum，namespace。
【规则3-1-1】类型名中每个英文单词的第一个字母大写，其它小写。缩写字当作普通字处理，即只有首字母大写。可以将所设计系统的缩写词作为前缀。区分名字中各单词尽量不用下划线。
例如：类AVAFactory中的AVA表示Armament Virtual Assembly。
### 3.2 函数命名
【规则3-2-1】函数名中首字母小写，其后每个英文单词的第一个单词的第一个字母大写，其它小写。
【规则3-2-3】不属于任何class的函数名采用“小写加下划线”的方式。
【建议3-2-4】全局函数的名字应当使用“动词”或者“动词＋名词”（动宾词组）。类的成员函数应当只使用“动词”，被省略掉的名词就是对象本身。
例如：  draw_box();   /*不属于class的（全局）函数 */
box->draw();   /* 类的成员函数 */
### 3.3 变量命名
【规则3-3-1】变量和参数名中首字母小写，其后每个英文单词的第一个单词的第一个字母大写，其它小写。
【建议3-3-2】变量的名字应当使用“名词”或者“形容词＋名词”。
【规则3-3-3】用下面不同的前缀来修饰变量名以区分不同的作用域：（函数参数及局部变量一般不加前缀）
静态变量加前缀s_（表示static）。
全局变量加前缀g_（表示global）。
类的数据成员加前缀m_（表示member），可以避免数据成员与成员函数的参数同名。
为了防止某一软件库中的一些标识符和其它软件库中的冲突，可以为各种标识符加上能反映软件性质的前缀。例如三维图形标准OpenGL的所有库函数均以gl开头，所有常量（或宏定义）均以GL开头。
### 3.4 宏、常量和模板命名
宏指所有以宏形式定义的名字，包括常量和函数；常量也包括枚举中的常量成员。
【规则3-4-1】宏、常量和模板的名字全部大写，如有多个单词，用下划线分隔。
### 3.5 指针命名
【建议3-5-1】指针标识符建议以p开头。
### 3.6 命名时避免使用国际组织占用的格式
已知的被占用的格式：
双下划线开头   ISO C++，ANSI C；
包含双下划线   ISO C++；
单下划线开头   ISO C++，ANSI C；
E[0-9A-Z]开头   ANSI C；
is[a-z]开头    ANSI C；
to[a-z]开头    ANSI C；
LC_开头    ANSI C；
SIG[_A-Z]开头   ANSI C；
str[a-z]开头   ANSI C；
mem[a-z]开头   ANSI C；
wcs[a-z]开头   ANSI C；
_t结尾     POSIX；
其他国际组织占用的格式。
## 第4章 基本语句
### 4.1 if语句
#### 4.1.1 布尔变量与零值比较
【建议4-1-1】不可将布尔变量直接与TRUE、FALSE或者1、0进行比较。
根据布尔类型的语义，零值为“假” （记为FALSE），任何非零值都是“真”（记为TRUE）。TRUE的值究竟是什么并没有统一的标准。例如Visual C++ 将TRUE定义为1，而Visual Basic则将TRUE定义为-1。
假设布尔变量名字为bFlag，它与零值比较的标准if语句如下：
if (bFlag)   /* 表示bFlag为真 */
if (!bFlag)   /* 表示bFlag为假 */
其它的用法都属于不良风格，例如：
if (bFlag == TRUE)
if (bFlag == 1)
#### 4.1.2 整形变量与零值比较
【建议4-1-2】应当将整型变量用“==”或“！=”直接与0比较。
假设整型变量的名字为iValue，它与零值比较的标准if语句如下：
if (iValue == 0)
if (iValue != 0)
不可模仿布尔变量的风格而写成：
if (iValue)   /* 会让人误解 value是布尔变量， */
if (!iValue)   /* 不过按照变量命名规则，iValue应为整型变量。 */
#### 4.1.3 浮点变量与零值比较
【规则4-1-3】不可将浮点变量用“==”或“！=”与任何数字比较。
千万要留意，无论是float还是double类型的变量，都有精度限制。所以一定要避免将浮点变量用“==”或“!=”与数字比较，应该设法转化成“>=”或“<=”形式。
假设浮点变量的名字为x，应当将
if (x == 0.0)   /* 隐含错误的比较 */
转化为
if ((x>=-EPSINON) && (x<=EPSINON))
其中EPSINON是允许的误差（即精度）。
#### 4.1.4 指针变量与零值比较
【建议4-1-4】应当将指针变量用“==”或“！=”与NULL比较。
指针变量的零值是“空”（记为NULL）。尽管NULL的值与0相同，但是两者意义不同（0的意义更宽泛一些，既可以表示NULL指针，又可以表示’\0’，更可以表示整数0，因此可能让人糊涂。注意：指针p == 0 的写法在任何标准的C/C++编译器里都不会产生错误的代码，反对这样用的理由是代码的可读性)。假设指针变量的名字为p，它与零值比较的标准if语句如下：
if (p == NULL)   /* p与NULL显式比较，强调p是指针变量。 */
if (p != NULL)
不要写成
if (p == 0)    /* 容易让人误解p是整型变量。 */
if (p != 0)
或者
if (p)     /* 容易让人误解p是布尔变量。 */
if (!p)
### 4.2 for语句
【建议4-2-1】建议for语句的循环控制变量的取值采用“半开半闭区间”写法。
示例4-2(a)中的x值属于半开半闭区间“x∈[0, n)”，起点到终点的间隔为n，循环次数为n。

相比之下，示例4-2(a)的写法更加直观，尽管两者的功能是相同的。

{

}for (int x=0; x<=n-1; x++)
{
…
}示例4-2(a) 循环变量属于半开半闭区间    示例4-2(b) 循环变量属于闭区间
### 4.3 switch语句
【规则4-3-1】每个case语句的结尾不要忘了加break，否则将导致多个分支重叠。如果有意使多个分支重叠，则应该在故意没有break的地方加注释。
【规则4-3-2】不要忘记最后的default分支。即使程序真不需要default处理，也应该保留语句default，这样做并非多此一举，而是为了防止别人误以为你忘了default处理。
## 第5章 函数设计
本章重点论述函数的接口设计和内部实现的一些规则。函数接口的两个要素是参数和返回值。C语言中，函数的参数和返回值的传递方式有两种：值传递（pass by value）和指针传递（pass by pointer）。C++ 语言中多了引用传递（pass by reference）。
### 5.1 参数
【规则5-1-1】参数的书写要完整，不要贪图省事只写参数的类型而省略参数名字。如果函数没有参数，则用void填充。
【规则5-1-2】参数命名要恰当，顺序要合理。参数的顺序要遵循程序员的习惯。一般地，应将目的参数放在前面，源参数放在后面。
【建议5-1-3】如果参数是指针或者引用，且仅作输入用，则应在类型前加const，以防止该指针或引用在函数体内被意外修改。例如：
void StringCopy(char *strDestination，const char *strSource);
注意：const char * 和 char * 是两种完全不同的类型，但是编译器可以自动完成char * 到const char * 的转换（反过来不行）。这意味着如果函数参数在可以（或应该）加 const 的地方没有const，函数则可能在某些情况下不能用。如：
void foo(char *str1, char *str2);
void foo(char *str1, const char *str2);
在C++中这是两个完全不同的函数，在C中则不能这样写。第1个函数不能被这样调用：
char szBuf[256];
foo(szBuf, “这样只能调第2个函数”);
【建议5-1-4】避免函数有太多的参数，参数个数尽量控制在5个以内。如果参数太多，在使用时容易将参数类型或顺序搞错。
【建议5-1-5】尽量不要使用类型和数目不确定的参数。
C标准库函数printf是采用不确定参数的典型代表，其原型为：
int printf(FORMAT, ...);  /* const char* FORMAT */
### 5.2 返回值
【规则5-2-1】不要省略返回值的类型。规定任何C++/ C函数都必须有类型。如果函数没有返回值，那么应声明为void类型。
【规则5-2-2】函数名字与返回值类型在语义上不可冲突。
【建议5-2-3】不要将正常值和错误标志混在一起返回。正常值用输出参数获得，而错误标志用return语句返回。
### 5.3 函数内部实现
不同功能的函数其内部实现各不相同，看起来似乎无法就“内部实现”达成一致的观点。但根据经验，可以在函数体“入口处”和“出口处”从严把关，从而提高函数的质量。
【建议5-3-1】在函数体的“入口处”，对参数的有效性进行检查。
很多程序错误是由非法参数引起的，我们应该充分理解并正确使用“断言”（assert）来防止此类错误。
【规则5-3-2】在函数体的“出口处”，对return语句的正确性和效率进行检查。
如果函数有返回值，那么函数的“出口处”是return语句。我们不要轻视return语句。如果return语句写得不好，函数要么出错，要么效率低下。
