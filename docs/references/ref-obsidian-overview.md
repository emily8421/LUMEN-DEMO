## 1. 产品定位

Obsidian 是一款本地优先（local-first）的个人知识管理（PKM）工具。核心主张：**笔记数据完全由用户掌控，不依赖任何云端服务或专有格式**。

- 免费个人使用；官方同步（Sync）/发布（Publish）服务为可选付费项，用户也可用第三方工具自行同步
- 目标用户：习惯"卡片笔记法"（Zettelkasten）、需要梳理复杂知识网络、不希望被单一平台锁定数据的用户
- 常见场景：个人知识库、读书 / 学习笔记、日记、项目与任务管理、写作大纲整理

## 2. 技术架构

### 2.1 底层技术栈

| 层次 | 技术选型 | 说明 |
|---|---|---|
| 运行时 | Electron | Chromium + Node.js，支撑跨平台桌面应用（Win/macOS/Linux） |
| 应用逻辑 | TypeScript | 核心业务逻辑 |
| 编辑器内核 | CodeMirror 6（CM6） | 早期为 CM5，1.0 版本起重写为 CM6，带来 Live Preview 能力 |
| 移动端 | Capacitor | 同一套 Web 技术栈封装为原生应用外壳 |

### 2.2 数据存储层（核心设计哲学）

- **纯文本文件系统**：不使用数据库，不使用专有格式；每篇笔记即一个 `.md` 文件，直接存放于用户本地文件夹（"Vault"）
- **元数据实时解析**：双向链接（`[[..]]`）、标签（`#tag`）、YAML frontmatter 等均由 Obsidian 在本地内存中实时解析 Markdown 文本得到，**不落地为独立数据库**；删除 / 移动 `.md` 文件不会破坏"数据完整性"
- **配置隔离**：仓库内隐藏目录 `.obsidian/` 存放插件配置、主题、工作区布局等 JSON，与笔记正文分离

### 2.3 编辑器：CodeMirror 6 与 Live Preview

- CM6 采用状态（`EditorState`，不可变）与视图（`EditorView`）分离的函数式架构；所有编辑通过 `Transaction` 描述状态变化
- **Live Preview（实时预览）实现方式**：
  1. 用 **Lezer**（CM6 配套增量解析器）实时把 Markdown 解析为语法树
  2. 基于语法树，通过 `Decoration` API 在不改变底层文本的前提下改变显示（如隐藏 `**` 符号但渲染为粗体样式；把 `[[链接]]` 渲染为可点击样式）
  3. 复杂内容（图片、公式、内嵌笔记）通过 `WidgetType` 用自定义 DOM 替换 / 插入到文本流中
  4. **光标感知**：光标进入某语法元素时"揭示"原始 Markdown 语法，方便编辑；光标移开后恢复渲染态
- 三种编辑模式：Source Mode（纯源码）/ Live Preview（默认，混合渲染）/ Reading View（走独立渲染管线，输出静态 HTML，用于导出、打印、纯阅读）
- **插件扩展点**：CM6 的 Extension 机制对插件开放——`ViewPlugin` / `StateField` 添加自定义 Decoration，`EditorSuggest` 实现自动补全，`registerEditorExtension()` 注入自定义扩展到每个编辑器实例

## 3. 双向链接与图谱

- 笔记间通过 `[[笔记名]]` 建立链接，形成网状而非树状的知识组织方式
- **反向链接面板**：任意笔记可查看"有哪些笔记链接到我"，弥补树状目录检索不到的隐性关联
- **全局图谱视图**：可视化展示全部笔记间的连接关系
- **本地图谱（Local Graph）**：以当前打开的笔记为中心、展开 N 跳的局部图谱，随文档切换自动刷新，是日常导航工具而非仅供展示
- **图谱过滤器**：可按标签、文件夹、链接类型等条件实时过滤图谱节点

## 4. 插件生态

- 官方开放 JavaScript/TypeScript Plugin API，插件运行在与主应用相同的 Electron/Chromium 环境中，可直接操作 DOM、读写 Vault 文件、监听事件
- 分为核心插件（官方内置，可开关）与社区插件（第三方开发，插件市场安装）
- API 覆盖编辑器（自定义语法渲染）、文件系统（读写笔记）、UI（侧边栏 / 状态栏 / 命令面板扩展）三个维度

## 5. 同步与协作

- **Obsidian Sync**：官方端到端加密同步服务，本质是对 Vault 文件做差异同步
- **第三方方案**：因数据即普通文件，用户也常用 iCloud、Git、Syncthing、坚果云等自行同步，架构上与应用本身解耦
- **已知短板**：Obsidian 本质是单机工具，缺乏原生多人协作与团队权限模型，团队场景依赖第三方同步工具凑合，无法做到细粒度的空间隔离与权限分级

## 6. 设计哲学总结

> 本地文件为唯一数据源（Local-first）+ 内存索引提供强大功能 + 开放 API 支持无限扩展

这一设计牺牲了云端原生协作的便利性，换来数据可移植性、长期可用性（不依赖厂商存续）与高度可定制性——这也是本文档被引入 LUMEN 参考资料库的核心原因：LUMEN 同样采用 Markdown 文件 + 索引数据库的分层存储，与 Obsidian 的理念高度接近，但需要在团队协作、权限隔离上补足 Obsidian 的原生短板。
